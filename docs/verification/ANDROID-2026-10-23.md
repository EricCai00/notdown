## 桌面回归边界

先尝试全量浏览器回归。四个独立临时知识库分片并行时，机器可用物理内存降至约 75 MiB，并出现文件读取错误及断言失败；停止分片，未将该运行记为全量通过。

改用单 worker、独立端口和构建，运行保存、数据库、编辑器、导航、页面元数据、源码文件、附件、联系人与运行环境相关的 101 项检查：91 通过、10 失败。详情见 `android-desktop-focused.log`。

在独立目录导出未包含本次修改的 Git HEAD `ae5f3e69f663a20060eba2c18cb820e6505812b9`，重新构建并运行 10 项比较用例，得到 5 通过、5 失败（`android-baseline-e2e.log`）。以下测试在该基线中也失败：

- `editor.spec.ts:37`：普通段落 Tab 嵌套。
- `editor.spec.ts:617`：页面提及与子页面的旧显示断言。
- `editor.spec.ts:887`：插入菜单；当前广泛运行另遇到同名父页面 `<option>` 的选择器冲突。
- `internal-reference.spec.ts:27`：插入 example 列表。
- `people.spec.ts:116`：斜杠菜单的联系人选择器。

当前代码的联系人文件单独在新临时知识库重跑，5 通过、1 失败；唯一失败为上述 `people.spec.ts:116`，与基线相同。其余 5 项在广泛运行中失败、在独立运行中通过，不能据此宣称广泛套件全部通过。日志为 `android-people-isolated.log`。

未为了此次 Android 移植修改这些桌面交互或放宽其断言。并行进行的其他工作区改动仍保留。

## 设备验证与剩余边界

手机授权后，已在 Android 16 设备（型号标识 `2602BRT18C`）完成 APK 安装与保留应用数据的更新，启动命令成功，首次 WebView 连接确认应用初始化完成。实际界面显示 `On device` 和保存状态；升级后通过应用私有目录确认 `metadata.json` 和 Markdown 页面文件仍存在，未执行卸载或清除应用数据。

真机观察发现切换源码后顶部视图按钮的选中状态未跟随变化，已修复并更新设备上的 APK；手机浏览器测试同时补充了双向切换时的 `aria-pressed` 断言。

后续设备未保持 Notdown 在前台，WebView 调试连接持续超时，自动化未能进入独立临时知识库。因此没有把真机编辑、备份或进程恢复的完整流程记为通过，也未向原有知识库写入测试内容。

仍需验收 Android WebView 下真实中文输入法的组合输入、系统文件选择器/ZIP 保存、返回手势、切后台与进程回收，以及低内存设备表现。Chrome 触屏和 JVM 文件测试不能替代这些项目。当前是已安装的离线开发版本，尚未完成全部真机验收，也没有跨设备同步、外部 SAF 文件夹编辑或正式发行签名。
