## Native Markdown editing core (Phase 1)

Input will instantly enter the document in this window and the existing CAS saving process, and the source code will not be lost when switching; click the formula again to continue editing, and the edge of the window will automatically adjust the position of the floating layer. The preview only supports KaTeX syntax and does not implement full LaTeX; inline formulas still use the original editing window.

After selecting text, a floating format menu is displayed: the first A button provides text color/background color and the color recently used in this edit, as well as bold, italic, underline, strikethrough, inline code, clear format, normal link and inline formula conversion. Color/underline/strikethrough/formula are displayed according to the current expansion switch; the color follows the span encoding with a limited name, and the same text currently uses a text color or background color. Single block text selection can be converted into text, H1 – H4, list, to-do, quote and code; cross-block selection supports inline format, hidden block conversion in the table, and no pop-up menu in the code block. Supports undo, save and reopen, Esc close, and Ctrl/ ⌘+ Shift+M focus menu; no selection AI operations or collaborative comments yet provided.

The + and six-point handles of the top-level block are uniformly aligned according to the outer boundary of the block, and 12px is retained between the handle and the block; the list mark, check box, reference padding and folding arrow do not change the position of the action bar, and the action bar of the nested list is indented with the real level. The six-point menu is prioritized to be expanded on the left side of the handle with a 8px spacing; narrow windows are prioritized to be moved above/below the block, and the height is limited and scrolled according to the available space. When super-tall blocks fill up the window, they may still be partially blocked. The first segment of Callout uses the overall drag handle outside the container, and subsequent sub-blocks can be dragged independently. Notion `<callout>` You can click the icon to search, select or paste emoji/symbols, or remove them; modifications support undoing and saving and reopening. The icon selector currently does not provide image upload; native Alert still retains its prompt type and original encoding.

Column support drags the separator line between columns to adjust the width of adjacent columns, including multiple columns and nested columns; supports undo/redo, Esc cancellation, double-click equal width, arrow key fine-tuning, and save and reopen. Source code mode uses CodeMirror 6; clipboard pasting and text dragging are unified according to the LF/CRLF line wrapping format of the current document to avoid mixed line wrapping leaving isolated carriage returns, resulting in blank line height and line number misalignment.

In ordinary paragraphs and form elements `<br>` The resolution is editable, and no longer packages the entire text into HTML previews; the blank unit format does not display the block insertion prompt.

Ordinary table cells are edited as rich text: Enter/Shift+Enter inserts internal line breaks, disables Slash block menu and block conversion, and drags in units of the entire table. The paragraph boundaries of pasted rich text are converted to line breaks; when inserting multiple blocks of Markdown, they are retained as grammatical text within the cell, and nested blocks are not generated. Historical multi-segment cells can still be read. The internal `paragraph+` is only for compatibility and does not support any sub-blocks.

The upper spacing of the main text title is 16px, and the post-paragraph spacing of the previous block does not overlap with it; the first title does not add additional upper spacing.

Build with `npm run build -- --outDir .run/e2e-dist` first, then set these two variables and run with `npx playwright test --output test-results/e2e-isolated --reporter=list`; avoid parallel processes cleaning each other's build artifacts or trace files.

## subsequent sequence

1. Extended interactive acceptance: system Chinese IME, keyboard search, narrow screen, touch, screen reader and large documents.
2. Editor extensions: table row and column management, arbitrary block nesting, automatic scrolling of frame selection edges and cross-page dragging; expansion of the official Enhanced Markdown round-trip corpus.
3. Synchronized kernel: content-addressed snapshot + parent version + device ID; three-party merge without conflicting modifications, conflicts generate branches. Complements offline queuing, attachment hashing, tombstone removal, renaming, authentication and cross-device failover. The current CAS is only based on this, **has not completed cloud synchronization with**.
4. MyBase read-only integration: share existing attributes and Query semantics, access table/poster/map/tree/graph, parse `mybase:Q…` references, and then define authoritative sources and revision protocols for bidirectional modification.
5. Desktop packaging and mobile terminal: directory selection, application life cycle preservation, recycle bin batch management, offline mobile terminal, barrier-free keyboard and touch acceptance.

## third party sources

The extension source of Block Explorer has been reviewed: Meeting notes, Link preview and other nine functions are adapted to use `notion_*` ID, the old `local_*` configuration and links continue to be readable; the captioned pictures are general capabilities, and `local_figure` retains the Markdown classification. Color `notion_colors` and underline `notion_underline` have been started and stopped independently. The original `notion_colors` now only controls color. Current 127 items: Pandoc 89, Notion 22, other Markdown 16. Classification does not mean that Notion API interoperability has been achieved. For details, see [ Classification Audit ](../audits/EXTENSION-CLASSIFICATION-AUDIT-2026-09-22.md).

The actual dependencies are ProseMirror modules, CodeMirror, markdown-it, Lucide, etc., and the upstream license is retained. Markdown Lab calls Pandoc installed on the user's local machine; the project does not package the Pandoc executable file. The AFFiNE, AppFlowy, and Anytype source codes are used to understand hierarchies, page mentions, menus, focus, and filters; their document storage or complete application is not introduced. Vditor/Lute has been removed from runtime dependencies; the old build directory may still exist but is not referenced by the editor. Reference paths are listed in [ cross-reference ](../reference/NOTION-REFERENCE.md).
