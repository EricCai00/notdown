# Notdown

[English](README-2026-09-23.md) · **简体中文**

脚注区采用 `1. 正文`、`2. 正文` 的编号样式，保留当前主题颜色。多段落和代码按内容列对齐，正文仍使用上标引用。每条定义末尾提供 `↩` 返回按钮；重复引用时提供分别返回各处的按钮，支持键盘操作。显示编号和返回按钮不写入 Markdown。

**当前阶段的格式边界**：Notdown 集合已有 Markdown 方言与 Notion。自定义正文语法仅用于补足官方 Enhanced Markdown 不支持的 Notion block、已有 block 的属性、inline 和 style，且只能在 `syntax.variant: notdown` 启用；`notion-markdown` 仅启用官方文档定义的语法，显式扩展开关也不能越过此边界。能用已有方言表达的内容复用该方言，不能另造重复协议。旧文件和未知字段必须可恢复保留，不批量迁移用户内容。 已移除 `local_figure` 开关及新建入口，图文题注使用 Pandoc `implicit_figures` / `link_attributes`；旧 nest/columns/page 指令仅保留源码，不再新生成；Lab 的 `notdown-bookmark` 围栏恢复普通代码。九组 Notion 补充编码及日期提醒、列宽、折叠持久状态、本地同步参数仅在 Notdown 启用。官方 variant 的日期用官方字段编辑、折叠只改变视图，不写补充属性。官方 Meeting notes 暂保留源码，其本地服务属性仅在 Notdown 解释。表格合并和题注使用 Pandoc grid table；不再新生成带这些结构的 NFM 表格。完整范围见 [语法边界与整改](../audits/CUSTOM-SYNTAX-AUDIT-2026-09-23.zh-CN.md)。

**People 本地通讯录**：侧栏 People 提供联系人的新增、搜索、查看、编辑、删除与恢复，可记录姓名、邮箱、电话、组织和备注。正文输入 `@` 可搜索联系人，方向键选择、Enter 插入、Esc 取消；日期建议继续可用，`/Mention person` 也接入联系人选择。点击提及打开详情；稳定 ID 支持同名联系人与改名，删除不清除已有提及。联系人保存为 `people/*.yaml`，页面仍保存 Markdown；改名只更新显示，不批量改写笔记中的后备名称。更新使用 `baseRevision`，冲突保留双方 YAML，并在表单中提供比较。**Person 只是本地联系人，不是登录用户、工作区成员或权限主体，不发送提及通知，也不提供协作或跨端同步。** `@` 补全用于 Page／Split 的富文本区；源码区保留原文编辑，可通过插入菜单添加。详见 [People 格式与边界](../features/PEOPLE.zh-CN.md)。

2026-09-23 源码定位修复：`Ctrl+E` 使用与页面相同的脚注显示投影对应 Markdown 原文位置，修复页面包含脚注后因块数不一致而完全跳过定位的问题；正文与页尾脚注均可跳到对应源码行，当前行号高亮。长块内部仍按相对位置近似定位，尚未实现任意嵌套语法的逐字符映射。

脚注统一显示在文末的一条分隔线下，按正文首次引用顺序编号、排序，重复引用沿用同一编号。定义可直接编辑，但不提供拖拽手柄、块菜单或块插入按钮；未引用定义保留在末尾。包括容器内定义在内，显示排序不改变 Markdown 定义的原始存储位置；保存、撤销与重开沿用同一文档和本地 CAS。

插入菜单修正：Tabs 放入 **Notion advanced**，HTML document / Web embed 放入 **Notion embeds**；Footnote 放入 **Markdown inline**，使用 `[1]` 图标。脚注引用插入光标处，定义追加到文末，保留段落连续性；Inline note 使用独立名称和图标。脚注定义仍保存为可编辑正文，并非删除定义、仅保留引用。

2026-09-22 内容合集：**Notdown** 现在组合现有 Notion 内容与 Markdown 扩展，默认提供脚注、定义列表、Mermaid、Markdown 容器、多种表格、上下标、高亮、引用文献等；H5/H6 保留，不再套用 Notion 的 H4 上限。`/` 菜单分为 Notion basic / advanced / media / embeds / inline / style 和 Markdown blocks / inline，全部条目注册图标，并补格式与行内公式入口。容器内混合内容支持编辑写回、原文保留和扩展关闭。**数据库、完整 Notion 云端自动化、协作与跨端同步仍未实现**；合集不等于所有互斥方言语法同时兼容。完整边界见 [Notdown 内容合集](../reference/NOTDOWN-SUPERSET.zh-CN.md)。本条覆盖下文“Notdown 仅继承 Notion”“Notdown H5/H6 转为 H4”的历史说明。

页面标题区域悬停时按需显示 **Add icon / Add cover**，移开收起且不改变标题位置；已有图标可直接点击更换或移除，已有封面通过横幅右上角操作，键盘聚焦操作入口和触摸设备仍可使用。图标可搜索、粘贴 emoji／符号、替换或移除。有封面的页面显示全宽横幅，图标压在横幅下缘，右上角可更换、拖动或用方向键调整纵向位置、下载封面。**Gallery** 收录随应用提供的 136 张本地封面并按原图库分组；也可上传图片到当前知识库、输入图片 URL／知识库 assets 路径或移除封面。Unsplash 标签提供外部查找入口及图片 URL 输入，尚无应用内搜索。封面地址和位置作为页面 YAML 属性保存，仍走本地版本检查。页面 **Properties** 折叠区统一收纳页面 YAML 属性、正文 YAML / MultiMarkdown metadata 与 Pandoc title block；各格式采用与现有属性一致的图标行，显示前两个字段摘要及剩余数量。点击摘要直接打开 CodeMirror 代码编辑器，提供 YAML 专用高亮、Pandoc / MMD 标记高亮、行号、缩进、查找和局部撤销；**Save changes / Ctrl+Enter / Ctrl+S** 提交，Cancel / Escape 丢弃草稿。保存检查语法与单一元数据块边界，注释、未知字段和原存储位置保留，关闭 Metadata values 后仍可编辑源码。提交后支持正文撤销；打开详情时后台刷新不覆盖草稿，版本冲突继续保留双方内容。

页面、Callout、Button 与 Tab 共用的图标选择器收录 [Unicode Emoji 18.0](https://www.unicode.org/Public/18.0.0/emoji/emoji-test.txt) 的 3972 个完整 emoji 与独立组件，按十组浏览，并可按英文 CLDR 短名、[Other Keywords](https://www.unicode.org/emoji/charts-18.0/emoji-list.html) 或字符搜索；肤色、性别、组合和旗帜序列均可选。热门快捷项另有少量自定义中文搜索词；所有已收录 emoji 在热门、最近使用、搜索结果和分类中悬停均显示英文 CLDR 短名，未收录的自定义符号标为 Custom icon。肤色序列沿用未加肤色版本的关键词；五个独立肤色组件只按名称或字符搜索。未收录第三方 `:shortcode:` 别名全集。选择器和 **Settings → Reading experience → Emoji style** 提供系统默认、[Google Noto](https://github.com/googlefonts/noto-emoji) 与 [OpenMoji](https://github.com/hfg-gmuend/openmoji) 图形风格，设置保存在当前浏览器，应用内正文和图标优先使用所选字体；字体未覆盖的新 emoji 回退到系统字体。页面 YAML 与正文仍只保存 Unicode 字符，不因切换图形风格改写。Noto 字体使用 [SIL OFL 1.1](../../src/assets/fonts/LICENSE-Noto.txt)；OpenMoji 图形由 OpenMoji 项目设计，使用 [CC BY-SA 4.0](../../src/assets/fonts/LICENSE-OpenMoji.txt)。未提供 Apple 专有图形、自定义 emoji 上传或跨设备同步风格设置。

**Pandoc title block 的 title 与页面标题双向联动**：页面标题框、重命名菜单、元数据字段／代码编辑及完整源码中的标题变更一起保存；作者、日期和其他正文保留。首次打开已有不一致页面时，以有效且非空的 Pandoc title 为准更新页面标题，仍走本地 CAS；未识别或禁用的 Pandoc 语法不联动，YAML / MMD 的 title 保持独立。页面标题沿用 500 字符上限。尚未实现图标图片上传、封面自由裁剪、评论或跨端同步。

Block Explorer 已补入桌面工作簿 `markdown` / `extended` 的 154 条语法，以及 Pandoc 手册 89 个扩展名的说明。在对象、方言和扩展详情的 **Syntax guide** 查看原始示例、单元格位置、相关编码、官方来源及更正；可以按 `extended!A53:E53` 检索。12 个非 Markdown 格式选项明确标为无 Markdown 输入语法。语法关联、当前开关状态、原文保留和完整实现分开说明；已发现的数学/上下标/高亮能力映射缺漏、自定义 HTML 锚点与 GFM tagfilter 差异、Literate Haskell 不完整规则尚未在本次修复，详见[语法说明核对报告](../audits/SYNTAX-CATALOG-AUDIT-2026-09-22.zh-CN.md)。没有实现 GitHub 短引用服务、R/knitr 执行器或 Notion 数据库；仍只有本地 CAS 与冲突分支，无跨端同步。

HTML embed 与 Web embed 可从块插入菜单或 `/html`、`/web` 直接插入。在 Notdown 方言中默认可用；其他方言不启用这两个补充编码；已有 HTML iframe 继续按其上游语法处理。HTML 空块点击 **Create or upload HTML**，支持上传／拖放 `.html` 文件或直接输入 HTML 代码，无 AI 创建区；确认后显示独立预览，可重新编辑。Web 空块点击 **Embed anything…** 输入 HTTP(S) 链接，已有 Typora iframe 也使用同一链接面板。提交可撤销，保存和重载保留内容及未知属性；Escape／点击外部取消草稿，外部更新或切页关闭旧面板。HTML 内容随页面保存，预览禁用脚本，尚不导入相对路径依赖或打包网站资源；Web 是否可显示取决于站点嵌入策略，提供原网页链接，未提供 Web 文件上传或自动将普通分享地址转换为各平台专用嵌入地址。沿用本地 CAS 和冲突分支，无跨端同步。

## 对象统一与本地能力

Button 对照 [Notion 官方功能说明](https://www.notion.com/help/buttons)及[官方界面示例](https://www.notion.com/help/guides/automatically-generate-blocks-pages-with-buttons)改为紧凑描边按钮，直接点击执行，悬停或键盘聚焦后通过齿轮打开内联配置。支持名称、emoji、默认／灰／蓝样式，以及动作增删、复制和排序：插入 Markdown 块（按钮上方／下方、页首／页尾，含预览）、确认弹窗、打开本地页面或 HTTP(S) 网址。新增按钮立即配置，Done 保存，Cancel／Escape 丢弃配置草稿；动作先校验，确认取消不产生部分正文修改，整组执行可一次撤销。旧 `action/target` 按钮及未知字段保留。需先开启 `local_button` 插件；尚未提供数据库增改、通知、邮件、Webhook、变量公式、Notion 云端联动或原生块模板编辑器，模板目前用 Markdown 编辑。仅本地 CAS 保存与冲突分支，无跨端同步。编码和限制见[本地对象与服务](../reference/LOCAL-OBJECTS.zh-CN.md#button)。

Breadcrumb 以页面图标、名称和斜杠构成紧凑行内导航，无卡片外框；正文块和顶部导航均从 vault 中的根页面显示到当前页面，每一级（包括当前页）都可点击跳转。路径随页面改名、移动和父级更新刷新，正文窄屏可换行。旧 `path` 属性及未知字段保留在 Markdown 中，但不再决定导航内容，也不提供手工路径编辑。

图片、媒体、书签、Tabs、AI／Meeting notes、同步块等块属性，通过拖动手柄菜单的 **Properties…** 打开独立窗口；正文元数据字段从页面 **Properties → 元数据摘要 → Edit fields** 打开。保存统一提交并可一次撤销，取消／Escape 丢弃未保存的字段草稿；目标块被外部更新或删除后禁止提交旧草稿。

Web bookmark 按 Notion 参考提供浅灰 **Add a web bookmark** 空态、链接输入弹层和带网站图标／标题／描述／网址的圆角卡片。通过 `/bookmark` 插入空块，或粘贴 HTTP(S) 网址后选 **Bookmark**；创建、修改链接及手动刷新时提取公开网页的 HTML 元信息，有封面时显示右侧缩略图。整张卡片可在新标签页打开，悬停可改链接、刷新或打开 Properties；Escape／点击外部取消输入，创建结果可撤销。元信息保存到 Markdown，重载不自动抓取；失败保留网址并允许重试，异步结果不会覆盖已修改或删除的块。抓取有超时、大小及重定向限制，不携带网站登录凭据，不访问私网地址；登录页、反爬网站、仅 JavaScript 渲染及仅 IPv6 的站点可能无法生成详情，可手工补充。这不是网页全文存档或跨端同步。

Tabs 使用简洁标签栏、浅灰圆角选中态与行尾加号，正文不再嵌套卡片边框。整块及内部子块从正文移向左侧 +／六点手柄时，经过内边距和空隙仍保持当前块的操作目标。再次点击当前标签、右键任意标签或按 ↓ / Shift+F10 打开菜单，可重命名、更换图标、左右移动及删除（至少保留一个标签）；← / → / Home / End 切换标签。修改仍写回 Markdown，可撤销；图标使用现有 `tab` 属性保存并保留未知字段。只读预览可切换标签，不修改正文；暂未提供标签拖动排序和标签专属链接。

方言名称不再附加 `(native)`、`(deprecated)` 或 `(core syntax)`；本地解析方式和旧版 GitHub 方言的弃用说明保留在说明区域。`gfm` 显示为 GitHub Flavored Markdown，`markdown_strict` 显示为 Original Markdown，内部标识保持不变；GFM 的 Spec／Docs 来源继续在扩展标签中区分。

Extensions 与 Block Explorer 保留当前方言的可配置规范语法、内置语法与 Others 分组；来源仅分为 Pandoc extensions、Notdown Notion extensions、Notdown Markdown extensions，Others 内按此顺序分区排列。Notdown blocks 归入 Notdown Markdown 扩展，不再单独置顶，名称和扩展 ID 与其他条目一致显示；Outside Markdown scope 仍作为不可启用的参考项放最后。CommonMark／GFM／CommonMark X 的基础规则在第二组只读显示，不提供虚假开关；缺少 Pandoc flag 的其他条目不会自动算作内置。规范语法标注必需／可选、GFM Spec／Docs、Typora 设置可选项，并链接官方依据；Pandoc 3.11 默认状态单独展示，修改勾选不会改变分组。此调整仅涉及列表展示，不新增语法支持。详见[扩展依据说明](../reference/EXTENSION-PROVENANCE.zh-CN.md)。

已按最新对象清单注册 **81 个内容对象**，覆盖 block、metadata、inline、character。Block Explorer 默认展示产品对象、别名、编辑能力与后续阶段；Child structures 单列有归属的子结构并双向链接所属对象。MMD metadata 归入 YAML front matter 对象，但按独立的纯文本语法解析，不冒充完整 YAML。Database reference 对象及专用节点已移除，原标签保留为 Unsupported。Inline raw source 已纳入 Content objects；文件引入的块级与行内位置共用 File transclusion。Mention agent、Inline media 及 Existing content 板块已移除；本地音视频 Markdown 链接保持普通链接，媒体标签仍表示块级媒体。详见[元数据与表外格式说明](../architecture/METADATA-AND-COMPATIBILITY.zh-CN.md)。菜单和块标签使用统一名称，语义别名仍可搜索；删除误拼别名 date ot reminder。

Block Explorer 的对象、方言和扩展两两双向链接，支持地址分享、刷新与前进／后退。按工作簿 `extensions` sheet 标注三类来源，展示全部 115 项：103 个 Markdown 扩展已接入本地执行路径，12 个 Outside Markdown scope 项始终排在最后且不可启用。`notdown_*` 配置键已改为 `notion_*`，旧键兼容读取；同名新旧键并存时新键优先，不批量迁移用户文件。工作簿原始状态与本地能力分别展示。详见 [目录分类与命名说明](../reference/CATALOG-RELATIONS.zh-CN.md)。

Callout / Alert 已合并；三种 TOC 编码共用目录节点；Bullet、Numbered、Task list item 使用三个底层节点，Heading 共享节点。管道、Notion、MultiMarkdown、网格、简单及多行表格统一为 table/row/cell/caption，可增删行列、合并／拆分单元格和编辑题注。新增 Tabs、手工书签、GitHub／OneDrive 链接预览、Breadcrumb、隔离 HTML embed、图片题注、Example list item、Native span、Small caps 及 Raw TeX 编辑路径。定义列表项可独立排序，元数据提供字段编辑，页面属性支持 cover。PDF 使用浏览器内嵌查看器及链接回退。逐项能力及源码编辑边界见 [对象 Roadmap](../architecture/CONTENT-OBJECT-ROADMAP.zh-CN.md)。

Settings → **OpenAI-compatible services** 配置端点、文本模型、转录模型和密钥。AI block 的 Generate 使用 `/chat/completions`，Meeting notes 的 Transcribe 使用 `/audio/transcriptions`，只在点击时发送相应文字或音频；异步结果不覆盖请求期间的新编辑。密钥保存在当前知识库 `.notdown/services.json`，不写入页面，不通过读取设置 API 返回。Button 的多步骤本地动作见上文；日期提醒在应用打开时运行并在重新打开时补发；Synced block 支持本地来源刷新、暂停于本地编辑的可选自动刷新及 CAS 发布。这些不是后台操作系统调度或跨端同步。具体格式与服务边界见 [本地对象与服务](../reference/LOCAL-OBJECTS.zh-CN.md)。

界面统一使用英语，包括主应用、编辑器菜单、语法扩展设置、Markdown Lab、无障碍标签及应用错误提示；内置 Lab 示例也使用英语。现有知识库笔记、页面标题和自定义属性保留原文，不做自动翻译。当前未提供界面语言切换。

一个以本地 Markdown 为正文真相的笔记应用原型。目标是把 Obsidian 的文件透明性与 Notion 的页面组织、阅读体验结合起来。

比较了工作区中的 SiYuan、AFFiNE、AppFlowy、Anytype 和 AnyBlock。当前使用 **ProseMirror 连续编辑器 + Markdown 文件内核**：页面/存储参考思源，列表层级和块交互参考 AFFiNE、AppFlowy。早期 Vditor 实现已被替换，以支持独立列表项、连续选区、统一撤销和固定的页面链接节点。上游 clone 和 MyBase 项目保持独立；本项目不是完整上游 fork。理由与代码证据见 [选型记录](../architecture/FOUNDATION.zh-CN.md)。

默认「页面」将阅读、编辑和块整理合并：直接点击正文编辑，拖动左侧六点手柄调整顺序，Markdown 随之保存。正文工具栏提供 **源码 / 双栏 / 页面** 三种视图，双栏左侧为带高亮的 CodeMirror，右侧可直接编辑并同步滚动；`Ctrl+E` 在页面与源码之间切换。三个视图共用一份草稿和撤销历史。悬停块时在左侧显示 + 与六点手柄。交互参考见 [Notion 交互参考](../reference/NOTION-REFERENCE.zh-CN.md)。

Split 同步滚动按视口顶部所在块的源码起止范围与实际页面高度双向对齐；源码换行、窗口缩放和内容高度变化后重新测量，页尾留白允许最后几个块滚到顶部。空白分隔行对应块间空隙；关闭同步可独立滚动，重新开启后跟随最后滚动的一侧。当前以顶层块为映射单位，列表、表格及嵌套容器内部按整体高度定位；折叠隐藏、移入属性区或重排的内容不能保证逐行对应。

`Enter` 创建新块，`Shift+Enter` 在当前段落/列表项内换行。列表项行首退格先去掉标记，退出列表后的空行退格直接回到上一项末尾。启用普通块层级扩展后，文本支持 `Tab` 建立父子关系及 `Shift+Tab` 提升。新页面默认 [Notion-flavored Markdown](../FORMAT.zh-CN.md)；旧页面继续使用原语法，打开视图不会自动迁移正文。

Notion 方言编辑时保留原有顶层块间空行，新增或重写块的边界默认留一个空行；列表项保持紧凑，代码块内部空行保留。排版空行不会生成额外空块。修改过的复合容器内部仍可能规范化间隔，详细规则见 [正文格式](../FORMAT.zh-CN.md)。

## 原生 Markdown 编辑核心（第一阶段）

数学块插入后立即打开贴在块下方的 TeX 编辑浮层：空块显示 “Add a TeX equation”，输入时上方实时显示 KaTeX 预览；Done／Enter 完成，Shift+Enter 换行，Escape 或点击外部收起并保留已输入内容。输入即时进入本窗口文档及现有 CAS 保存流程，切换源码不丢失；再次点击公式可继续编辑，窗口边缘自动调整浮层位置。预览仅支持 KaTeX 语法，不执行完整 LaTeX；行内公式仍使用原有编辑窗口。

选中文字后显示浮动格式菜单：首个 A 按钮提供文字色／背景色及本次编辑最近使用的颜色，另有粗体、斜体、下划线、删除线、行内代码、清除格式、普通链接与行内公式转换。颜色／下划线／删除线／公式按当前扩展开关显示；颜色沿用有限名称的 span 编码，同一文字当前使用一种文字色或背景色。单块文字选区可转换为正文、H1–H4、列表、待办、引用及代码；跨块选区支持行内格式，表格内隐藏块转换，代码块内不弹出菜单。支持撤销、保存重开、Esc 关闭以及 Ctrl/⌘+Shift+M 聚焦菜单；尚未提供选区 AI 操作或协作评论。

顶层块的 + 与六点手柄统一按块外边界对齐，手柄与块之间保留 12px；列表标记、复选框、引用内边距和折叠箭头不改变操作栏位置，嵌套列表的操作栏随真实层级缩进。六点菜单优先在手柄左侧展开并留 8px 间距；窄窗口优先移到块上／下方，按可用空间限制高度并滚动，超高块占满窗口时仍可能局部遮挡。Callout 的首段使用容器外侧的整体拖动手柄，后续子块可独立拖动。Notion `<callout>` 可点击图标搜索、选择或粘贴 emoji／符号，也可移除；修改支持撤销与保存重开。图标选择器目前不提供图片上传；原生 Alert 仍保留其提示类型与原编码。

分栏支持拖动列间分隔线调整相邻列宽，包括多栏及嵌套分栏；支持撤销／重做、Esc 取消、双击等宽、方向键微调和保存重开。比例以 `<column width-ratio="…">` 本地属性保存到 Markdown，HTML 预览／导出同步显示，窄屏改为纵向排列并保留比例。Notion Block API 有 `width_ratio`，但官方 Notion-flavored Markdown 尚未定义列宽属性；不承诺该本地扩展能经 Notion Markdown API 保留，详见 [格式说明](../FORMAT.zh-CN.md#分栏页面和附件)。

源码模式使用 CodeMirror 6；剪贴板粘贴和文本拖入按当前文档的 LF／CRLF 换行格式统一，避免混合换行留下孤立回车，造成空行高度和行号错位。

普通段落和表格单元格中的 `<br>` 解析为可编辑换行，不再将整段文字包装成 HTML 预览；空单元格不显示块插入提示。

普通表格单元格按富文本编辑：Enter/Shift+Enter 插入内部换行，禁用 Slash 块菜单及块转换，拖动以整张表格为单位。粘贴富文本的段落边界转为换行；插入多块 Markdown 时保留为单元格内的语法文字，不生成嵌套块。历史多段单元格仍可读取，内部 `paragraph+` 仅用于兼容，不表示支持任意子块。

正文标题上方间距为 16px，前一块的段后间距不与其叠加；文首标题不额外增加上方间距。

  H1–H6 使用 30 / 26 / 23 / 20 / 18 / 16px 的平缓递减字号并保持加粗，H6 与正文同为 16px，通过字重区分；编辑器和 Markdown 预览使用一致的字号层级。开启 Settings → Color headings by level 后，六级标题依次使用棕、绿、蓝、紫、赭黄、玫红；关闭后仍通过字号区分层级。

  页面代码块提供可搜索的语言选择、常见语言语法着色、复制、`Wrap code` 长行显示切换，以及块下方的单行 caption。Wrap 只折行显示，不修改代码和保存的 Markdown。未内置着色规则的语言保持纯文本，超长代码块为保证编辑流畅也保持纯文本。caption 使用已有 fenced code attributes 写入，仅在 Notdown 或支持该扩展的 Markdown 方言中可编辑；官方 Notion-flavored Markdown 不定义代码 caption 编码，菜单会提示切换方言。当前 caption 是纯文本，不提供 Notion API 富文本 caption 往返；详见[正文格式](../FORMAT.zh-CN.md)。

正文、Button、Breadcrumb 等紧凑块之间统一保留 4px 间距；代码、表格、Callout 等容器块前后保留 12px，标题前为 16px，相邻间距不叠加。Callout、Tabs、分栏等嵌套正文使用相同规则，容器首尾不额外增加外边距；列表项和表格单元格内部保持紧凑。此调整只影响排版，保留正文中的显式空块与 Markdown 原文。sequence、flow 与 Mermaid 图表在预览区域水平居中。

页面内顶层脚注显示在正文末尾，定义仍可直接编辑并保留 Markdown 中的位置；嵌套容器中的定义仍留在容器内。提示块之间保留间距，图表按可用宽度显示。Typora 的未定义完整／折叠引用显示为链接文字并提示目标未定义，不虚构跳转地址；未定义脚注保留原文。脚注视觉顺序与源码顺序不同，键盘遍历仍遵循文档结构。

Typora 宽松嵌套列表中的无序父任务与子任务使用一致的复选框解析，未修改时保留大小写任务标记的原文。按用户应用实测，Typora 方言中有序项的 `[ ]` / `[x]` 保留为文字；GFM 方言仍生成复选框。Typora 默认仅去掉其支持转义的标点前的反斜杠，可显式开启 `all_symbols_escapable` 扩大范围。HTML 过滤后无预览内容时保持空白，仍可展开编辑。`textarea` 显示只读文本框，支持 rows/cols，持久修改通过“编辑 HTML”；行内 HTML 不显示标签原文，Typora 方言也一样。粘贴 Markdown 不自动复制其相对路径附件，图片须上传到知识库；对照样本提供可上传的 PNG。

Typora 对照修正：默认保留段落／列表项内单换行（可关闭 `hard_line_breaks`），顶层块之间 3 个空行映射为 1 个空段落、5 个映射为 2 个（每增加两个换行符新增一个空段落），首尾也支持空段落，可点击输入、删除和撤销；这是 Notdown 的编辑器约定，不是 CommonMark/GFM 标准语法。未修改时逐字保留原文，编辑空段落后按 Markdown 段落边界写回。嵌套列表／引用内部的连续空行尚未映射为空段落。Obsidian 预设也默认显示软换行，可关闭 `hard_line_breaks` 使用严格换行行为。有序列表仅接受点号标记，`1)` 保留为普通文字；CommonMark/GFM 继续接受右括号标记。普通、引用与自动链接显示下划线，编辑区 Ctrl/⌘ + 点击打开外部链接。尖括号自动链接不再误入未知 HTML 回退。测试样本见 [Typora 对照文档](../../docs/fixtures/typora-comparison.md)。目前未复刻 Typora 编辑、打印和导出各自独立的空白设置，也不代表所有版本的完整兼容。

**已新增 Typora、Obsidian 独立方言，并逐项接入用户清单中的 62 条语法。** 包括图表、提示块、注释、高亮、属性、MMD 引文／BibTeX、CriticMarkup、文件嵌入、元数据变量和复杂表格。默认值、需要开启的扩展与每条实现边界见 [当前 62 条支持矩阵](../reference/PRODUCT-SYNTAX.zh-CN.md)；这不表示完整复刻所有产品语法。

- 已接入 **12 个原生预设、114 个内置扩展开关**：Typora、Obsidian、Notion-flavored Markdown、Notdown、CommonMark、GFM、Pandoc Markdown、CommonMark X、Original Markdown、PHP Markdown Extra、MultiMarkdown、旧 GitHub Markdown。上游预设按各自规则定义，Notdown 继承 Notion 语法并默认开启项目块；仅 Pandoc 预设使用 Pandoc 3.11 快照。具体差异与兼容范围见 [原生方言](../reference/NATIVE-DIALECTS.zh-CN.md)。Slash、输入规则及块类型菜单依据配置提供可用操作。
- 十个 Markdown 预设支持按开关解析 HTML、定义列表、脚注、逐行排版和 fenced Div；HTML 默认显示，源码可展开编辑。另接入标题／引用前空行、代码围栏种类、列表打断段落、转义、智能标点、上下标、缩写、Emoji，以及三种元数据块的识别与原文保留。Notion codec 保持独立规则，尚未适配这些新增开关。
- 方言是默认规则集合，扩展是覆盖值。切换方言/扩展重新解释相同源码；停用的特有块保留为原文块。配置保存在页面 YAML 的 `syntax` 字段，和正文一起通过 `baseRevision` 保存；冲突分支保留各自配置。
- **日常编辑不需要 Pandoc**。页面输入使用 ProseMirror 事务；源码输入立即更新草稿，70 ms 防抖后在浏览器原生解析。复用未改子树的指纹和原文，两个编辑视图按差异更新。
- 原生 reader 实现本地支持矩阵中的核心语法，不代表完整复刻 Pandoc 的所有规则与扩展组合。`sourcepos` 提供块级行范围；相对路径重定位针对具备 sourcePath 的 Markdown 链接／图片；`markdown_in_html_blocks` 当前处理 Div 容器；Gutenberg 用于纯文本导出。精确 Pandoc AST 双向映射、第三方插件安装、后台 Worker 和整篇增量解析仍未实现。源码使用通用 Markdown 高亮，大文档解析仍可能阻塞主线程。

架构背景见 [原生编辑核心设计](../architecture/MARKDOWN-ENGINE.zh-CN.md)，当前实现以 [对象 Roadmap](../architecture/CONTENT-OBJECT-ROADMAP.zh-CN.md) 为准。HTML 经过清理；脚注正文可编辑，缺失定义明确提示；Div 保留未知属性，只显示允许的属性。Pandoc 引文可用本地 bibliography／CSL 文件和已安装 Pandoc 提供 citeproc 预览；HTML 导出尚不等待该异步预览。Raw TeX 保留为目标格式源码，浏览器不执行 TeX；LaTeX 宏作用于后续 KaTeX 公式。正文元数据独立于页面 YAML，不自动覆盖页面属性。Markdown Lab 的 Pandoc 对照范围单独标注。

复杂图表／表格、HTML 混合块、元数据和嵌入文件采用**预览＋块内源码编辑**，不宣称完整所见即所得编辑；嵌入文件只读，最多每 4 秒刷新。Mermaid 按需加载且本地渲染，iframe 单独隔离。

## 运行

**Windows 一键启动：双击此目录的 `start.cmd`。** 它在后台启动本地文件服务和网页服务，检查页面、API 及编辑器模块后再打开浏览器。重复启动会复用同一知识库的运行实例；日志保存在 `.run/`。首次安装需先执行 `npm ci`。

需要 Node.js 24 和 npm。在此目录执行：

```powershell
npm ci
npm run dev
```

打开 <http://127.0.0.1:4317>。本地文件服务监听 `127.0.0.1:4318`。编辑器依赖由 Vite 从本地安装的包加载，常规编辑不依赖公共 CDN。

`npm run dev` 是前台开发命令，关闭其终端会停止服务；日常体验可使用上述独立后台启动入口。

```powershell
npm run build
npm start
```

构建后由本地文件服务在 <http://127.0.0.1:4318> 同时提供页面和 API。首次启动隐式默认知识库时创建五篇示例笔记；现有知识库或显式配置的目录不会被自动填充。

自选知识库：

```powershell
$env:VAULT_PATH = 'D:\Notes\Notdown'
npm run dev
```

当前仅支持一个本地服务进程操作同一知识库。不要把开发服务直接暴露到公网；认证、远端同步与多进程锁尚未实现。

## Markdown Lab：外部渲染器与实时双栏预览

启动服务后打开 <http://127.0.0.1:4317/markdown-lab.html>，或点击侧栏底部的 **Markdown Lab**。生产构建入口为 <http://127.0.0.1:4318/markdown-lab.html>。

- 左侧 CodeMirror 源码编辑器：行号、高亮、自动换行、查找和撤销；右侧可切换清理后的页面预览与外部程序返回的原始 HTML 文本，支持双向同步滚动与独立滚动。
- **libMultiMarkdown CLI · direct HTML** 与 **Markdown.pl · direct HTML** 是两个独立的外部程序直出入口。Pandoc 方言预览也调用本机 Pandoc CLI，先用所选 reader 生成 JSON AST，再由 Pandoc 写出 HTML，因此不再重复列出 Pandoc CLI 直出项。`markdown_mmd` 是 Pandoc 的 MultiMarkdown reader，不等同于 libMultiMarkdown CLI。后者使用 snippet 模式并关闭文件包含。程序或 reader 缺失时选择器标注不可用，源码仍保留。HTML 标签页显示生成的 HTML 文本；页面标签页清理 HTML 后再显示。
- 方言预览覆盖本机 Pandoc 3.11 的八种 Markdown reader：`gfm`、`commonmark`、`commonmark_x`、`markdown`、`markdown_mmd`（Pandoc 的 MultiMarkdown reader）、`markdown_phpextra`、`markdown_strict`、`markdown_github`，另有自有 codec 的 `notion-markdown` 和 `notdown`。Lab 中这些方言的显示名与主编辑器的 `variant` 名称一致；内部 ID 不变。前八种使用 Pandoc AST 预览链路；Notion 与 Notdown 不需要 Pandoc。未安装的 reader 在界面中标注不可用。
- 「扩展与插件」从本机 Pandoc 获取其各方言的扩展及默认值；切换方言、开关扩展只重新解释源码，不转换或重写正文。Lab 的 Notion 方言目前整体启用；Notdown 预设与页面编辑器共用默认值，并可逐项关闭语法和块扩展。
- 直接渲染模式使用程序自己的语法规则，不接受 Lab 的 Pandoc 扩展开关或块插件；设置按钮会禁用。现阶段没有可安装的第三方块插件。
- 支持打开 UTF-8 Markdown 文件、下载当前源码（`Ctrl+S`）、当前窗口会话草稿恢复。文件导入是副本，下载不写回原路径；当前方言/扩展配置保存在窗口草稿中，不嵌入下载的 Markdown。CodeMirror 使用 LF 换行，不承诺导入文件字节级往返。
- 预览采用 180ms 输入防抖，取消旧请求并拒绝过期结果；错误保留源码并标明旧预览。公式使用本地 KaTeX，HTML 经过清理。

Pandoc 模式需要本机安装 Pandoc，或在启动服务前设置 `PANDOC_PATH`。MultiMarkdown CLI 从 PATH 或 Windows `Program Files/libMultiMarkdown *` 安装目录查找，也可设置 `MULTIMARKDOWN_PATH`。Markdown.pl 需另行安装 Perl 与原版脚本，并在启动前设置 `MARKDOWN_PL_PATH` 为脚本绝对路径；Perl 不在 PATH 时设置 `PERL_PATH`。更改安装或环境变量后重启服务。当前验证版本为 Pandoc 3.11 与 libMultiMarkdown 6.7.0；本机 Markdown.pl 1.0.1 由 Git for Windows 的 Perl 运行。

**当前边界：** Lab 是独立的源码编辑与只读输出，不接入知识库自动保存、页面属性、块拖动或右侧编辑；普通笔记的保存流程保持现有规则。GFM / CommonMark / CommonMark X 按 Pandoc 原生行号同步，Notion 按 codec 行号同步；其他 Pandoc reader 使用块位置估算，直接渲染模式只能按文档进度同步。复杂表格/脚注及重排内容不能保证精确对应。源码高亮使用通用 Markdown 规则，实际语义以所选程序为准。最多接受 128,000 个 UTF-16 码元，第三方插件安装、任意 Lua Filter 执行和多格式导出尚未提供。

融合方式及具体困难见 [Markdown Lab 架构与兼容边界](../features/MARKDOWN-LAB.zh-CN.md)。正文仍是 Markdown 真相；Pandoc AST 仅在预览请求内存中产生，不作为持久化块数据库。

扩展清单见 [Pandoc 扩展与 Markdown 方言完整对照](../reference/PANDOC-EXTENSIONS.zh-CN.md)：按本机 Pandoc 3.11 核对手册的 89 个扩展名，逐项列出八种方言的支持、默认值与差异原因，并区分非 Markdown 扩展、Filter 和当前 Lab 显示边界。

`Ctrl+P` 搜索；正文编辑器外也可用 `Ctrl+K` 搜索，正文内保留该组合键给编辑器。`Ctrl+E` 切换页面/源码：进入源码时定位到可见光标所在内容块；光标不在视野内或仅滚动阅读时，定位到当前可见内容。长代码块、列表等按块内相对位置定位，尚非逐字符映射；返回页面保留此前阅读位置。切换前收取待处理输入，不改写正文。`Ctrl+S` 立即保存。浏览器草稿按窗口隔离，刷新同一窗口可以恢复；窗口关闭后尚未写入磁盘的草稿不是完整的恢复机制。页面标题和父页面不随正文重复存储，均在 YAML 中。

## MyBase 和 MCP

MyBase 位于 `D:\Workspace\mybase`，其权威源码是 `.mybase`；RDF 是查询/交换投影，不能替代有序的 Markdown 正文。当前通过工作区设置导出当前页面的 `.mybase` 元数据，没有自动写入主库或执行 Query。详细映射、现有 API、视图以及实际解析验证见 [MyBase 集成契约](../reference/MYBASE.zh-CN.md)。

先启动本地文件服务，再让 MCP 客户端启动桥接进程，例如通用 JSON 配置：

```json
{
  "mcpServers": {
    "notdown": {
      "command": "node",
      "args": [
        "D:/Workspace/note-app/markdown-workbench/node_modules/tsx/dist/cli.mjs",
        "D:/Workspace/note-app/markdown-workbench/server/mcp.ts"
      ],
      "env": { "NOTE_API_URL": "http://127.0.0.1:4318" }
    }
  }
}
```

这是客户端配置示例，没有修改任何现有 AI 客户端配置。不同客户端的外层配置形式可能不同；桥接进程本身使用标准 MCP stdio。更新工具必须使用读取返回的 `revision`，不会自动吞掉冲突或强行重试。

示例中的 `D:/Workspace/note-app/markdown-workbench` 是当前本地目录，请按实际克隆位置调整。应用名称为 Notdown；改名后首次打开会迁移当前浏览器中的旧版设置和草稿。
