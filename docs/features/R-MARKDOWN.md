- Receive the current window pending input before running and execute the current draft snapshot. The results do not enter Markdown, metadata, undo history, or CAS updates; the file body is not overwritten. The original preservation and conflict rules remain unchanged.
- When only executing changes to the node's own code, language, or block header options, the results will be marked as expired; restoring to the source code last run will remove the prompt. Editing of the normal text or other nodes does not expire the result, nor cancel a single execution of the node; modifying a running node cancels the old snapshot. Leaving the page, stopping the run, or clearing a running result cancels the request and the R process tree, and late-arriving results are not attached to the new document. Closing an inline overlay or clearing completed output does not reset session variables.
- The source code can contain up to 128 and 000 characters. Each service has a maximum of two Notebook sessions, executed serially in the same session; and a maximum of two entire Knit runs. A single request can take up to 60 seconds, and the console and returned results can each take up to 8 MB. Notebook idle 15 minutes will be recycled; terminate the process and clean up the temporary directory when stopping, timing out, restarting, leaving the page or closing the window. Common R code errors retain existing session variables so they can be corrected and continued.
- The editor inherits the native Pandoc subset and is not committed to full Pandoc compatibility. Full R options are left to the installed knitr/rmarkdown version; unknown options are left as is. The run output follows these official runtime libraries, and the editor Extensions switch is not used as a knitr or Pandoc run parameter.
- There is currently no cross-restart session, persistent Notebook output, `.nb.html` import/export, statement-by-statement run, row-level execution indicator, queued scheduling, debugger, or background automatic execution. Other language engines that the code can explicitly install or call are outside the scope of this round of verification.
- YAML `output` is retained as is, but HTML is fixed for running within the app; no PDF/Word export, Shiny, JavaScript htmlwidgets or MathJax result previews are provided. Markdown Lab does not automatically execute R.
- Does not automatically copy the entire vault or import directory to the run directory. Relative data files, child documents, external bibliography, templates, etc. require user code to provide accessible paths; the temporary directory cache is not retained across runs.
