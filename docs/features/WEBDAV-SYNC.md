# 坚果云 WebDAV 同步

桌面和 Android 使用同一 WebDAV 同步后端。坚果云地址为 `https://dav.jianguoyun.com/dav/`；使用账号邮箱和“安全选项 → 第三方应用管理”生成的应用密码，不能填写网页登录密码。

2026-10-24 已使用用户提供的应用凭据完成真实坚果云连接检测：认证、临时文件读写、原始 ETag 条件更新、错误与过期版本拒绝均通过。未启用用户知识库同步，未进行真实跨设备或安卓真机验收，也未测量线路速度。

## 连接步骤

1. 登录自己的坚果云账号，在 **账户信息 → 安全选项 → 第三方应用管理** 中为 Notdown 生成应用密码。密码只填入 Notdown 设置，不需要发送到聊天。
2. 桌面打开 **Workspace settings → Cloud sync**；Android 打开 **Notebook options → Cloud sync**。
3. **Sync provider** 选择 **Nutstore / WebDAV**。服务器地址自动填写坚果云地址；填写 **WebDAV account**、**Application password** 和远端目录，例如 `Notdown/My-notebook`。
4. 点击 **Sign in**。这一步会在服务端的 `Notdown-checks` 目录中创建并清理随机命名的子目录，检查读写和条件写入保护；检测失败不会启用同步。坚果云不允许通过 WebDAV 删除顶层目录，因此空的检测父目录会保留，不要把它选作知识库目录。
5. 在电脑端选择新建云端知识库、填写名称并点击 **Enable sync**。远端目录应为尚未使用的新目录，避免与现有文件、其他应用的目录混用。安卓只能连接已有云端知识库，不能执行新建。
6. 第二台设备填写同一账号、应用密码和**完全相同的远端目录**，登录后选择已有知识库，再启用同步。无需 Supabase 项目或自建公网服务器。

如果初始化被网络中断，远端目录已存在但没有有效索引，应用会保留它并停止。可以先断开这次配置，选一个新的远端目录重试；不要用不明内容覆盖既有目录。切换其他账号、目录或同步服务前也应先断开当前连接；本地和远端内容都会保留。

首次创建同一远端知识库请只在一台设备上操作，完成后其他设备选择已有知识库。坚果云对已存在目录的 MKCOL 仍可返回 201，并忽略 `If-None-Match`；应用会先检查目录及索引是否存在，但不能承诺两个设备同时初始化空目录时的原子排他保护。已有知识库的入口更新仍受实际验证过的 `If-Match` 保护。

## 连接错误

- `sandbox name is too long` 对应坚果云顶层目录名过长；连接检测使用短名称和独立子目录，避免旧版检测名称触发此错误。
- 坚果云的 ETag 可能没有双引号。应用保留原始标记用于 `If-Match`，仍拒绝弱 ETag，并验证错误、当前及过期版本的写入行为。
- WebDAV 失败会显示实际的同步错误及 HTTP 状态，不再误报为本地文件操作失败。认证错误检查应用密码和目录权限；限流错误等待冷却，不要反复点击登录。

## 网络与请求限制

- 桌面使用本地 Node 服务发起请求；Android 使用受限原生 HTTPS 请求，支持 PROPFIND、MKCOL 等 WebDAV 方法，并拒绝跟随重定向传递凭据。
- 手机浏览器预览仍受浏览器 CORS 限制。预览里的本机测试服务可用，不代表真实坚果云允许该浏览器跨域访问；真实手机接入应使用 Android APK。
- WebDAV 自动同步的两次尝试至少间隔约一分钟；无变化时只读取小型入口文件。每批最多提交 32 项变更，避免每个页面分别更新远端索引。
- 当前每设备、每知识库使用每 30 分钟 240 次请求预算。坚果云文档给出的免费账号限制为每 30 分钟 600 次，账号的其他设备和应用也会消耗请求；本地预算不等于服务端额度保证。
- 遇到 429/503 会保留内容并按 Retry-After 或默认冷却时间暂停；重启不会清除已保存的冷却状态。401/403 后停止自动重试，使用 **Sign in again** 更新应用密码。
- 同步速度取决于用户的实际宽带/移动网络、坚果云线路、请求限额和文件大小。本次没有测量真实坚果云速度，也没有验证是否需要代理。

## 存储与并发约定

- 每个知识库使用独立的远端文件夹，保存 Notdown 同步协议数据；不是将活动的本地 `metadata.json` 交给网盘客户端覆盖。
- 使用小型入口文件、压缩版本索引、不可变提交和内容寻址附件，不列举用户整个网盘。同步按索引取增量记录，因此不依赖超过 750 项的 WebDAV 目录响应。
- 连接检测在独立随机临时子目录中检查认证、读写、强版本标记和 `If-Match`，仅清理本次检测创建的子目录。不会把不支持条件写入的服务降级为无条件覆盖。
- 更新入口文件使用原始 ETag；并发失败保留待上传操作，不刷新版本强制覆盖。下一次同步重新检查原始资源版本，正文冲突复用现有处理。
- 请求预算、服务端限流退避和较低自动检查频率共同控制请求量；账号还有其他设备或应用时，以坚果云返回的限制为准。

## 当前边界

- 远端目录保存专用同步协议数据（压缩索引、提交记录和附件块），不能与其他软件的 WebDAV 目录混用，也不应手工编辑索引。各端本地正文仍是普通 Markdown。
- 索引和单个压缩提交解压后上限 16 MiB，单附件上限 64 MiB；普通应用上传入口仍遵守现有大小限制。云端历史和未完成提交产生的未引用对象暂不自动回收，因此也会消耗空间。
- 凭据和请求预算存于设备的 `.notdown/sync/connection.json`，应用 ZIP 备份不包含该目录。WebDAV 应用密码需要保存在本机以便再次连接；它不是 Supabase 的短期登录密码。
- 当前为前台同步，无端到端加密、后台 Worker 或多用户共享。若服务端实际条件写入语义与检测结果不一致，不能将其当成可靠同步服务。

测试命令为 `node --import tsx --test tests/unit/webdav.test.ts`、`npm run test:sync` 和 `npm run android:build`。通用同步边界见[云同步说明](CLOUD-SYNC.md)。坚果云的[应用密码与 WebDAV 规则](https://help.jianguoyun.com/?p=2064)为配置参考。
