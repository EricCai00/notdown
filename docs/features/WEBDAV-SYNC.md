<a id="连接错误"></a>

## Connection errors

- `sandbox name is too long`The corresponding top-level directory name of Nut Cloud is too long; connection detection uses short names and independent subdirectories to avoid old version detection names triggering this error.
- ETag of NutCloud may not have double quotes. The application retains the original tag for `If-Match` , still rejects weak ETag , and verifies write behavior for errors, current and expired versions.
- If WebDAV fails, the actual synchronization error and HTTP status will be displayed, and it will no longer be falsely reported as a local file operation failure. For authentication errors, check the application password and directory permissions; for current limiting errors, wait for cooling down and do not click to log in repeatedly.

<a id="网络与请求限制"></a>

## Network and request limits

- The desktop uses the local Node service to initiate requests; Android uses restricted native HTTPS requests, supports PROPFIND, MKCOL and other WebDAV methods, and refuses to pass credentials following redirects.
- Mobile browser preview is still limited by browser CORS. The local test service in the preview is available, which does not mean that the real Nut Cloud allows the browser to access cross-domain; real mobile phone access should use Android APK.
- WebDAV The two attempts of automatic synchronization are separated by at least about one minute; only the small entry file is read when there are no changes. A maximum of 32 changes can be submitted in each batch to avoid updating the remote index separately for each page.
- Every device, every knowledge base, is now using every single30 The minute240 The following requested budget: The free account limits provided by the Nut Cloud documentation are limited to one per person.30 The minute600 Other devices and applications in the account will also consume requests; the local budget is not equal to the service end guarantee.
- When encountering 429/503, the content will be retained and paused by Retry-After or the default cooling time; restarting will not clear the saved cooling state. Stop automatic retries after 401/403 and use **Sign in again** to update the application password.
- Sync speed depends on the user's actual broadband/mobile network, Nut Cloud circuit, request limit and file size. This time we did not measure the actual Nut Cloud speed, nor did we verify whether a proxy is required.

## Storage and concurrency contract

- Each vault uses an independent remote folder to save the Notdown synchronization protocol data; instead of handing over the active local `metadata.json` to the network disk client for overwriting.
- The indexing of the compression version, the unchanging submission and content address attachments, and the non-listing of the user's entire networking disk are used to index the incremental record simultaneously, so that it does not depend on more than one user.750 The following is a list ofWebDAV The directory responds.
- The connection check checks authentication, read-write, strong version mark, and `If-Match` in a separate random temporary subdirectory, and only cleans the subdirectory created by this check. Services that do not support conditional writing will not be downgraded to unconditional coverage.
- Update the entry file to use the original ETag; if concurrency fails, the upload operation will be retained, and the version will not be refreshed to force overwriting. The next synchronization rechecks the original resource version, and reuses existing handling of text conflicts.
- The request budget, server-side current limit backoff and lower automatic check frequency jointly control the request volume; when the account has other devices or applications, the limit returned by Nut Cloud shall prevail.

<a id="当前边界"></a>

## Current limitations

- The remote directory holds dedicated synchronization protocol data (compressed indexes, commit records, and attachment blocks) and cannot be mixed with other software's WebDAV directories, nor should the index be manually edited. The local text at each end is still ordinary Markdown.
- The upper limit after decompression of index and single compressed submission is 16 MiB, and the upper limit of single attachment is 64 MiB; ordinary application upload portals still comply with the existing size limit. Unreferenced objects generated by cloud history and unfinished submissions are not automatically recycled, so space will also be consumed.
- Credentials and request budgets are stored in `.notdown/sync/connection.json` on the device, and application ZIP backups do not include this directory. The WebDAV application password needs to be saved locally in order to connect again; it is not a short-term login password for Supabase.
- Currently front-end sync, no end-to-end encryption, background Worker or multi-user sharing. If the actual condition writing semantics on the server side are inconsistent with the detection results, it cannot be regarded as a reliable synchronization service.
