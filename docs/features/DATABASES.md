# Local databases and Notion database import

**English** · [简体中文](DATABASES.zh-CN.md)

Databases organize ordinary Markdown pages: every record has its own `pages/<page-id>.md`. Table cells and the property editor above the page share the same page properties. Desktop and mobile share database views and resource storage; cross-device use requires experimental [foreground cloud sync](CLOUD-SYNC.md). Notion API import creates local copies and does not write back to Notion.

## Creating and editing

If the front end has been updated and the old running back end does not have a database interface, ordinary pages can still be opened and saved; the sidebar and database entrance prompts to restart the back end. After updating the service, you can use **Check connection** to recheck. This compatibility is only for 404 of the database list interface; metadata corruption, permissions, and other service errors will still be reported.

1. sidebar **New database**, or in **Databases** Select from list **New database**, create the root database immediately, with the default name **New database**, there is no confirmation pop-up window. 2. Header **Add property** or **Add a property** of the record panel add text, number, check, date, single choice, multi-select, status, URL, email, phone, People or Relation fields. 3. Blue **New** or the new row entry at the bottom of the table creates a record. The open button next to the title expands the record panel on the right by default, and the table remains on the left; the title, attributes, and text can be edited in the panel. **Open as full page** Then enter the normal page, and continue to use the existing Page / Source / Split view for the text.
4. The database is automatically saved like the page, and changes are collected after a pause in continuous input, when leaving the cell or pressing Enter. Save the pending input before switching pages or databases; keep the draft and prevent switching when saving fails, only provide **Retry save** and **Discard draft and reload** at the error point, and no longer retain a separate database save menu.
5. The top tab switches the view, **New view** opens the layout selection panel, you can create Table, Board, Gallery, List, Calendar, Timeline, Chart, Feed, Dashboard, Form or Map, and then select the name and data source. **Filter**, **Sort** and **View settings** provide filtering, sorting, view name and display column settings; the search icon expands the current table search. Hiding columns and filtering records does not delete properties or pages, and the title column is always retained. The current tab remembers the last selected view for each vault and database, and restores the selection when it is reopened or the browser returns.

The numeric `0` and the boolean `false` retain their types. Date save start, optional end and existing time zone information. Radio, status and multi-select saving options ID, display names in colored labels and edit via options panel. Imported values ​​such as associations, contacts, and files are displayed as read-only; resolvable associations can open the local page imported in this batch.

Full-page databases use a compact title and view toolbar without a back-to-Databases button; the sidebar and breadcrumb provide navigation. New databases start without a custom title icon. The subdatabases, Child page and Link to page in the main text use the same single-line entry style, 16 px icon and underlined name, and separate cards are no longer given to the subdatabases. The record sidebar reuses the existing text editor without saving a new copy of the text. Save the pending text and attributes before closing the sidebar, opening the full page, or jumping; if a conflict occurs, keep the draft and prevent the jump, but you must still handle the conflict explicitly. You can explicitly select **Discard draft and reload** to abandon the draft of this tab and read the latest content. The conflicting archives will still be retained. The wide-screen table sits side by side with the record, the narrow-screen record panel overlays it from the right, and the wide table scrolls horizontally in its own area.

YAML / Pandoc overrides still take precedence over JSON: table and page property areas show valid values and mark document-controlled properties as read-only. Modifying the overlay value through source code or Metadata details will not cause the JSON default value to be modified but falsely reported that the effective value has changed.

## Timeline, Chart and Feed

Choose **New view → Timeline / Chart / Feed**, or change an existing view under **View settings → Layout**. These layouts reuse the same records, source ownership constraints, filters, search and page-opening preferences in full-page, inline and Wiki collection views. View settings are saved with revision checks; no page body is rewritten when changing layouts.

**Timeline** uses white range cards, month/day headers, weekend shading, a continuous Today line and a red date badge. Scroll horizontally across month/year boundaries; the grid extends as you approach its edges. Today and period arrows navigate without changing records. The 5 Years header groups numbered months beneath years. Edge-jump and date-navigation arrows use compact vector icons. **Time scale** opens a direct menu with Hours, Day, Week, Bi-week, Month, Quarter, Year and 5 Years; the saved scale survives reload. The chevron at the left and **Layout → Show table** toggle the sticky name column. The name column is hidden unless explicitly enabled, including in older views without a saved preference. Task titles remain on the date cards; showing or hiding the column is saved per view. **Layout → Timeline by** selects a Date property; a new Date property is added only when necessary. Hovering highlights a task's date range. Either edge shows a dark resize handle and its date; dragging highlights the card and updates the date preview. Drag the card horizontally to move its dates, or vertically to change the current view's manual row order when sorting and grouping are off. A translucent card and blue insertion line preview the drop. Escape cancels without saving; Alt + Left/Right adjusts one day. Date ranges and unknown date fields are preserved. Hours and Day display the written local clock time of timed values; timed, explicitly zoned and document-controlled dates remain read-only on the grid and can be edited in the record. Undated records, grouping, collapsed groups, filters, sorting and load limits remain available. Separate start/end properties are not implemented.

Task titles use a slightly larger, medium-weight font. When a date card is too short for its name, the full title extends past the card and remains clickable and draggable. The date bar, resize handles and dependency anchors still follow the scheduled range. **Property visibility** chooses and orders the properties displayed beside the title, including full date ranges, colored status/select tags, people and relations. Search, Hide all / Show all and Move up / Move down reuse the saved view settings. These inline values are read-only; opening the record provides property editing. When a scheduled card is outside the viewport, only a small arrow appears at the corresponding left or right edge; its title and properties are hidden. Edge arrows stay pinned while scrolling horizontally, including when the name column is shown. Hover for the task name/date range or click the arrow to return to the task. Undated rows retain a compact name and No date label.

**Dependencies** adds local **Blocked by** and **Blocking** relation fields to the source, without altering existing imported fields. Select prerequisites from a card connector or the Dependencies menu, or drag the gold circle from a prerequisite to its successor. The circle stays centered on its short connecting line as it enlarges on hover; a continuous solid arrow follows the pointer and outlines the target card. Drop on empty timeline space to create a linked page at that date, with the prerequisite's duration and the current overlap-shifting policy. Type its name directly on the new card; Enter or leaving the field saves it. Escape during the drag or releasing outside the timeline cancels without creating a page. Only dropping on a card connects an existing task; blank space in its row creates a new one. Translucent yellow arrows connect visible tasks and follow date edits, staying behind cards and titles even while connecting; activating an arrow removes the dependency. Table edits in either relation column update the same graph. Only Blocked by is stored in page properties; Blocking is an inverse read projection, including records outside the current filter/load limit. Self-links, foreign-source targets and cycles are rejected.

The Dependencies menu defaults to **Shift only when dates overlap** and lets you choose **Do not shift automatically** and the **Shift using** date property. In the database workspace, adding a dependency or editing that Date property moves overlapping successors to the day after their latest prerequisite ends, preserves duration, and continues through the full downstream chain, including filtered records. Existing dates do not change just by opening a view or changing the setting. Undated records remain undated; an overlapping timed, zoned or document-controlled successor blocks the proposed operation before it is queued. This scheduling applies to Timeline and Table workspace edits; direct API, Markdown and record-drawer changes are not automatically rescheduled. Each affected record and the view row order retain their own revision check. A conflict stops subsequent saves and preserves the remaining draft; a multi-record operation can be partially saved. **Manage in Calendar** opens or creates a local Calendar view using the same Date property and source; it does not connect an external calendar service.

New **People** properties select one or more local address-book contacts. **Manage people…** opens the existing address book. New **Relation** properties select other records in the same source. Unavailable references retain their saved data until explicitly deselected. Imported People/Relation values keep their existing read-only behavior.

**Chart** provides vertical and horizontal bars, lines, donuts and a number summary. Open **Configure chart** or **View settings → Layout**. Under **Chart type**, select an icon for vertical bars, horizontal bars, lines, donuts or a number summary; a blue border marks the selected type. Hover for the type name, or use Tab and Enter/Space to select it. The **Data** section sets the category (**What to show**), **Measure** (Count or a numeric property), calculation, sorting and date buckets. **Series by** splits bars or lines by a second property; bars can be stacked or placed side by side. Positive and negative stacks extend separately from zero. **Cumulative** is available for date categories with Count or Sum, and uses chronological category order. Average, minimum and maximum remain per bucket.

**Style** controls color, four chart heights, data labels, legend, grid lines and axis names. Lines offer smoothing and gradient fill; donuts offer a center total and percentage labels for slices large enough to read. Settings only show options relevant to the selected chart. Changing chart types preserves the current database scroll position while settings save. Charts fit the available width; dense category axes scroll inside the chart. Hover or focus a mark to see its value, then click or press Enter/Space to open its underlying record table. Cumulative points include the records contributing through that date. Open a record to edit it; Escape closes the table and restores focus. Legend buttons temporarily hide/show a category or series without changing stored filters or records. This visibility resets when the view reloads.

**Save chart as…** downloads PNG or standalone SVG, with an optional transparent background. Exports include the view title, visible plot and visible legend, with the chart's resolved styles. PNG resolution is capped for very wide charts. These downloads are browser-verified; Android native download handling has not been accepted on a physical device.

Calculations use all filtered/search-matched records regardless of the presentation load limit. Sum, average, minimum and maximum use finite numeric values; averages exclude missing values. Numeric line series break across missing observations. Multi-select records contribute once to each selected category/series; therefore category or stack totals can exceed the number of unique records. Number summaries aggregate records directly and cannot double-count due to grouping. Date groups use stored calendar dates; week buckets start on Monday. Missing dates are a separate, non-cumulative bucket. More than 200 categories or 50 series prompts you to narrow the data instead of silently truncating it. Donuts require non-negative values and a positive total. Settings retain revision conflict checks and do not rewrite page bodies. Saved drilldown views, formula/rollup execution and clipboard image copying are not implemented.

**Feed** displays a centered column of rounded cards with an author initial and name when `author` metadata is available, a relative update time, a large page title, and selected properties on a wrapping row. Document YAML/Pandoc author metadata takes precedence over shared properties; pages without an author show a neutral page icon and update time. Date ranges show both ends, people show names, relations show page titles (click to open available local records), and status values use colored pills. Optional page covers and a CommonMark body preview remain available. Click a card's title to open the page. Hovering subtly emphasizes the card's border and shadow without highlighting the title row.

**Layout → Page content** switches between a clipped preview and full content. **Property visibility** offers property search, **Shown in feed / Hidden in feed** sections, **Hide all / Show all**, and drag or up/down reordering. The title always stays visible. Changes apply and save automatically for this view while the menu stays open; failed-save drafts are retained. Filtering, sorting and grouping use the shared controls. The preview is sanitized, raw HTML is displayed as text, and unsupported Notdown syntax may remain literal. Source files are never rewritten by previewing them. Comments, reactions and view counts are not implemented.

Notion imports recognize these layout names and preserve the full remote definitions. Supported date and grouping references are mapped where available; unmapped chart configuration, timeline dependencies and collaboration features produce import warnings rather than claims of equivalent behavior. Existing imported fallback tables are not automatically converted.

## Dashboard, Form and Map

Use `npx tsx scripts/create-database-extra-examples.ts "<example-vault-path>"` to add three linked demonstrations and a guide to an explicitly selected example vault. The script refuses duplicate example names and verifies that existing Markdown pages remain unchanged.

**Dashboard** has separate viewing and layout editing modes. New dashboards start in **Edit dashboard**; existing dashboards open for viewing. Add widgets from saved views in any local database, or create a widget-specific table, chart, list, board, calendar or timeline. Up to twelve widgets can occupy up to four columns per row. Titles sit above aligned cards; hover or keyboard focus reveals controls. Narrow screens stack the widgets into one column.

In edit mode, use the drag handle to move a widget within or between rows, or drag to **Add a new row**. The title/context menu provides replace, duplicate, remove and keyboard-accessible move commands. Drag between columns to adjust relative widths and beneath a row to change its shared height; focused dividers also accept arrow keys. **Save layout** persists the captured revision. **Cancel editing** discards the draft. Failed saves retain the layout in this browser tab, including across reloads; stale revisions never silently overwrite another window's layout. Opening a legacy dashboard does not rewrite its old references.

**Configure widget** edits its name, visualization, properties, filters, sorts and groups in place. Widget settings are independent of the source view; duplicate widgets can diverge without changing original tabs. **Global filters** selects a data source and applies its conditions to every widget using that source. Conditions for multiple sources can coexist; properties with matching names in different sources are not automatically equated. Search covers all widgets. Changes made in viewing mode are temporary settings stored in the browser tab; use **Save widget settings** to persist them or **Reset temporary filters** to clear them.

Charts aggregate all matching records and resize with their cards. Other widgets limit displayed records; table widgets default to 50 and other layouts to 100 unless the underlying view specifies a limit. Table/list/board widgets open record pages, but editing record fields and moving records is done in the source view or page. **Open source view** opens the referenced database; unavailable sources remain visible as replaceable placeholders. Full-screen mode is available from the toolbar. Nested dashboards, form widgets, remote permissions, AI generation and cross-source property-name matching are not implemented.

**Form** turns visible writable properties into questions. Title is always required; **Layout → Required questions** configures other mandatory answers. Text, number, checkbox, date, select/status, multi-select, URL, email and phone are supported. Submission creates one record through the revision-checked vault API. Failed submissions retain answers, and drafts survive reloads within the same browser tab. Public links, anonymous submissions, conditional branching and file uploads are not provided.

**Map** shows records using a **Place** property, or existing numeric **Latitude** and **Longitude** properties (WGS84 degrees). Creating a map reuses the first Place property or adds one when needed; existing coordinate views keep their configuration. **Map by** switches between Place fields and coordinates. Add or edit a place from a record card, table cell or record panel: enter a name, address and coordinates manually, or explicitly **Search places**, select a result and **Save place**. Clear removes only this property value. Place names and addresses participate in shared text search, filtering and alphabetical sorting.

Use **Height** for Small, Medium, Large or Extra large, and **Color by** to use select/status/multi-select option colors. Multi-select uses the first selected option; missing values appear as an unclassified gray pin. The legend follows the records currently pinned. These controls also appear under **View settings → Layout**. Pan, zoom, **Fit all places** or **Show on map** to focus a record. A pin opens a card with its page title and **Open in Google Maps**; the record cards also open pages and Google Maps. Missing or invalid coordinates remain in the list. Only the first 100 located records, in the shared filtered/search-matched/sorted order, are pinned; additional records stay in the list with a notice. Presentation load limits do not silently remove map candidates.

OpenStreetMap tiles require network access and send map-area requests to the tile provider; record titles are not sent. Explicit place searches send only the entered query to the public [Photon geocoder](https://github.com/komoot/photon), based on OpenStreetMap data. Search coverage and availability vary; errors retain the entered values and manual coordinate entry works offline. Searches do not run while typing or replace a saved location until you select and save it. Google Maps receives the coordinates only when its link is opened. Place values are stored as `{ name, address, latitude, longitude }` in shared page properties; extra keys are preserved during edits. Saves retain page/schema revision checks and recovery drafts; map settings retain view revision checks and conflict recovery. Notion Place-property import, automatic address conversion, routing and background geocoding are not implemented.

## Data source management

The complete database and text-embedded database use **View settings → Manage data sources**, and can also be opened from **Source → Manage data sources**. Source management replaces the current content in the settings panel on the right, **Back** returns to the previous level, **Close** closes the entire group of panels. A database can contain multiple data sources, one of which is selected for each view.

The panel lists the sources owned by this database in **Source** and the sources of external access in **Linked**. Each source has one line, showing the name, the number of views currently in the database, and the **···** details entry. Details retain the original database, other databases using it, and their respective views; view links open the exact database and views. Hover the source name to see ownership and view names.

View the data source of the full vault: sidebar **Databases → Data sources**. Each data source in the list only occupies one row, and the name, original database and usage location/view are displayed in columns. You can search by data source, database or view name. **Browse all data sources** of the current database menu can also view the same list. The list is a read-only relational projection, no records are copied or metadata is written back, and the database in the recycle bin does not appear as an actively used location.

When the complete database contains multiple data sources, they are arranged by default as **database title → current data source title → view label**; when switching views, the second-level title changes with its data source. The complete page of a single data source only displays the database title by default; the embedded database only displays the title of the current data source by default. **Layout → Show data source titles** overrides the default display of data source titles, explicit selections are saved. The view label's hover tip shows the data source it belongs to.

The current data source title displayed in the complete database and embedded database can be directly clicked to edit and is no longer used as a drop-down menu entry. Automatically save after input, Enter or leave the input box to save immediately; Escape abandon the name that has not been submitted. The modification only updates the data source name, while the database container name, view name and text reference remain the original values; renaming the Linked location will also update the same source. The title is read-only when the source is unavailable. If saving fails or version conflicts, the name draft will be retained. Explicit retries will still use the original version, and modifications in other windows will not be automatically overwritten. Data source management is entered from **View settings → Manage data sources**.

## Layouts

Gallery defaults to **First image** under **View settings → Layout → Card preview**: it searches the body for its first image and falls back to the first block when none exists. **First block** shows only the first body block, including text, images or video. **Page preview** shows consecutive body blocks from the beginning, filling the available preview frame and clipping the overflow without scrolling or expanding the card. **Page cover** and **None** are also available; **Fit image** controls fitting versus cropping. Complete YAML/Pandoc title blocks are excluded. Page icons appear beside card titles and follow **Show page icon**. Existing explicit preview choices are retained. Previewing never edits Markdown.

**View icon**, available in view settings, the tab menu and new-view setup, searches the complete bundled Lucide symbol catalog. Each view saves its own choice; tabs, the overflow picker, the sidebar and Wiki selectors display it. **Use default icon** restores the layout icon. Duplicating a view retains its icon.
