# 脚注交互与正文块类型

[English](FOOTNOTES.md) · **简体中文**

核对日期：2026-09-23。

## 交互

- 对象分类统一为 `inline.footnote`。Pandoc 的 `^[…]` 仅作为 `inline_notes` 语法适配保留，没有独立的 Inline note 对象或插入命令；内部结构载体用于保留原文和编辑内容，不构成新对象类型。不会把已有行内脚注批量改写为引用式脚注。
- `^[…]` 在页面／双栏中显示编号上标，内容移到同一底部脚注区，与引用式脚注按出现顺序连续编号，支持预览、跳转、回跳、编辑和删除撤销。保存还原原位置的 `^[…]`，视图生成的标识不写入文件。行内脚注可跨源码行，支持行内格式与链接，但只能有一个段落；页面编辑拒绝拆段或改成块级内容，避免保存丢失内容。匿名脚注不出现在复用定义列表中。

- 插入引用时选择新建脚注并填写纯文本，或选取已有定义；多行输入建立多个可编辑段落。取消不新增脚注，复用不复制定义。
- 页面和源码编辑中的脚注插入命令均打开此对话框，保留插入位置；若对话框打开期间所属页面发生变化，则拒绝提交。
- 页面中的引用悬浮或获得键盘焦点时显示脚注正文的文本预览；编辑底部正文后预览随之更新。缺失定义显示缺失提示。
- 页面编辑中删除最后一个引用，会在同一撤销步骤删除定义和内部源位置锚点。删除部分重复引用保留定义；撤销恢复引用与定义。
- 打开文件、切换方言、外部投影和直接源码编辑不批量清理定义：导入时就未引用的正文可能是用户有意保留的资料。代码围栏中的 `[^id]` 字面量不计作引用。
- 正文仍写 `[^id]: ...`，续行缩进四个空格。底部集中显示只是同一个 ProseMirror 文档的投影，不新增存储协议。

## 规范核对

[Pandoc 官方脚注文档](https://pandoc.org/MANUAL.html#footnotes) 给出多块脚注、后续段落和代码块的例子；其“不能出现在列表、引用、表格等其他块内部”描述的是**脚注定义的放置位置**，不是禁止脚注正文包含这些块。

[PHP Markdown Extra 官方文档](https://michelf.ca/projects/php-markdown/extra/#footnotes) 明确说明脚注可包含块级元素，包括多个段落、列表、引用等，后续内容按列表条目规则缩进四个空格。脚注不是只有一段 inline text，也没有跨所有 Markdown 方言统一的块类型白名单。

本项目按当前方言及扩展开关解析脚注正文。单元测试验证 Notdown 下的多段落、标题、有序与无序列表、引用、代码块、表格、分隔线、定义列表和块公式在编辑后可序列化并重新解析。任务列表、图片、HTML、行块、Div 和图表等仍取决于对应语法开关，不承诺所有上游渲染器支持相同组合。

底部插入菜单提供当前已启用的 Markdown 块和行内格式；不提供子页面、分栏、Tabs、Button 等产品容器，也不提供嵌套脚注入口。这是本地编辑菜单边界，不把“所有 Notion block”解释成标准脚注能力。已有文件的扩展内容和未知内容继续由 codec 保留，不因菜单限制而删除。`notion-markdown` 仍遵守官方 Enhanced Markdown 边界，不因该功能启用脚注。
