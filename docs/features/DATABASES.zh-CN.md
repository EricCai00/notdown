# 本地数据库与 Notion 数据库导入

[English](DATABASES.md) · **简体中文**

数据库组织普通 Markdown 页面：每条记录都有自己的 `pages/<page-id>.md`，表格单元格和页面上方的属性编辑器共享同一份页面属性。桌面与手机共用数据库视图和资源存储；跨端使用需配置实验性[前台云同步](CLOUD-SYNC.zh-CN.md)。Notion API 导入为单向复制，没有 Notion 写回。

## 创建与编辑

如果前端已更新而运行中的旧后端尚无数据库接口，普通页面仍可打开和保存；侧栏及数据库入口提示重启后端，更新服务后可用 **Check connection** 重新检查。此兼容只针对数据库列表接口的 404；元数据损坏、权限及其他服务错误仍会报告。

1. 侧栏 **New database**，或在 **Databases** 列表中选择 **New database**，立即创建根层数据库，默认名称为 **New database**，没有确认弹窗。应用创建数据库 JSON、自有数据源、**Name** 字段和 **Table** 视图；随后直接点击数据库标题修改名称，按 Enter 或离开输入框保存。
2. 表头 **Add property** 或记录面板的 **Add a property** 添加文本、数字、勾选、日期、单选、多选、状态、URL、邮件、电话、People 或 Relation 字段。新字段的选项可逐行填写；点击已有表头打开属性浮层，通过 **Edit property** 逐项改名、调色、拖动或用上下按钮排序，也可追加或删除未被记录使用的选项。选项身份保持稳定。记录面板按属性名称显示字段，表格保留视图列顺序。
3. 蓝色 **New** 或表格底部的新增行入口创建记录。标题旁的打开按钮默认展开右侧记录面板，表格继续留在左边；面板中可编辑标题、属性和正文。**Open as full page** 再进入普通页面，正文继续使用现有 Page / Source / Split 视图。
4. 数据库与页面一样自动保存，连续输入暂停后、离开单元格或按 Enter 时收取修改。切换页面或数据库前先保存 pending 输入；保存失败时保留草稿并阻止切换，仅在错误处提供 **Retry save** 与 **Discard draft and reload**，不再保留单独的数据库保存菜单。
5. 顶部标签切换视图，**New view** 打开布局选择面板，可创建 Table、Board、Gallery、List、Calendar、Timeline、Chart、Feed、Dashboard、Form 或 Map，随后选择名称和数据源。**Filter**、**Sort** 和 **View settings** 提供筛选、排序、视图名和显示列设置；搜索图标展开当前表格搜索。隐藏列、筛选记录不会删除属性或页面，标题列始终保留。当前标签页记住每个知识库、数据库上次选择的视图，重新打开或浏览器返回时恢复该选择。

数字 `0` 和布尔值 `false` 保持其类型。日期保存开始、可选结束和已有时区信息。单选、状态和多选保存选项 ID，以有色标签显示名称，并通过选项面板编辑。关联、联系人和文件等导入值显示为只读；可解析的关联可打开本批导入的本地页面。

整页数据库使用紧凑的标题与视图工具栏，不显示返回 Databases 的按钮，可通过侧栏和面包屑导航。新数据库默认不显示自定义标题图标。鼠标悬停或键盘聚焦标题区域时显示 **Add icon** 和 **Add cover**。图标复用页面的 Emoji／Lucide 选择器，添加后与标题并排；移除后隐藏标题图标，引用入口仍使用统一的文档后备图标。封面横跨标题上方的内容区域，复用 Gallery、Upload 和 Link 选择器；悬停封面可更换、下载或调整位置，通过 **Save position** 或 **Cancel** 完成调整。移除封面时一并移除位置设置。标题、图标和封面属性使用同一套捕获版本与可恢复草稿，保留未知元数据，不改写 Markdown。旧宿主页或 Wiki Home 中由文档控制的值仍只能在源文档修改。内嵌数据库保留紧凑头部。

正文中的子数据库、Child page 和 Link to page 使用相同的单行入口样式、16 px 图标和带下划线的名称，不再给子数据库单独套卡片。它们仍分别保持原本的引用类型和导航目标，调整显示不会改写引用源码或父关系。

记录侧栏复用现有正文编辑器，不另存一份正文。关闭侧栏、打开完整页面或跳转前先保存待处理的正文与属性；发生冲突时保留草稿并阻止跳转，仍须显式处理冲突。可明确选择 **Discard draft and reload** 放弃本标签页草稿并读取最新内容，已有冲突归档仍保留。宽屏表格与记录并排，窄屏下记录面板从右侧覆盖显示，宽表格在自己的区域横向滚动。

YAML / Pandoc 覆盖仍优先于 JSON：表格和页面属性区显示有效值，并将受文档控制的属性标为只读。通过源码或 Metadata details 修改覆盖值，不会出现修改 JSON 默认值却误报有效值已改变的情况。

## 时间轴、图表和动态流

选择 **New view → Timeline / Chart / Feed**，或在 **View settings → Layout** 中切换已有视图。这些布局在整页、内嵌和 Wiki 集合视图中复用同一批记录、数据源归属约束、筛选、搜索和页面打开偏好。视图设置通过版本校验保存；切换布局不会改写页面正文。

**Timeline（时间轴）**使用白色日期卡片、月份／日期表头、周末底色、连续今日红线和红色圆形日期标记。横向滚动可跨月、跨年，接近边缘时自动扩展网格；Today 和前后周期按钮只导航，不修改记录。5 Years 表头按年份分组显示月份数字，离屏跳转和日期导航箭头统一使用紧凑的矢量图标。**Time scale** 直接打开 Hours、Day、Week、Bi-week、Month、Quarter、Year、5 Years 菜单，尺度保存后刷新仍保留。左侧双箭头与 **Layout → Show table** 控制固定名称列，名称列默认隐藏，未保存过该设置的旧视图也默认隐藏；任务标题保留在日期卡片上，手动显示或隐藏的选择按视图保存。**Layout → Timeline by** 选择日期属性，仅在必要时添加新日期字段。悬停卡片时高亮对应日期范围；两端悬停显示深色调整柄和日期，拖动边界时卡片高亮并更新日期预览。横向拖动卡片修改日期；未启用排序、分组时，纵向拖动可修改当前视图的手动行顺序，半透明卡片和蓝色插入线预览落点。Escape 取消且不保存；Alt + 左右方向键调整一天。保留日期范围及未知字段。Hours 与 Day 按存储的本地钟面时间显示带时间的值；含时间、显式时区或文档控制的日期不能在网格拖动，可在记录属性中编辑。无日期记录、分组、折叠、筛选、排序和加载上限继续可用。尚未实现独立起止属性。
- **表格行选择：** 悬停或聚焦行可显示在上方添加、拖动手柄和选择框。可逐行多选，按 Shift 选择连续范围，或通过左上角复选框全选当前显示的行。选择工具栏可将同一属性值赋给所选记录；文档元数据控制和只读值仍受保护。关闭排序和分组后，拖动所选行的手柄可按当前视图顺序一起移动。Escape 或工具栏取消按钮清空选择。筛选、折叠分组和加载上限限定选择范围。每条记录保留版本检查；冲突会停止后续保存并保留剩余草稿，因此批量修改可能只保存部分记录。

任务标题采用稍大、适度加重的字体。日期卡片较短、放不下名称时，完整标题会延伸到卡片外，仍可点击打开或拖动。日期条、两端调整柄和依赖连接点仍按实际排期定位。通过 **Property visibility（属性可见性）** 选择并排序标题右侧显示的属性，包括完整日期范围、彩色状态／选择标签、人员和关联。搜索、Hide all / Show all 与 Move up / Move down 沿用并保存当前视图设置。行内属性仅用于展示，打开记录可编辑属性。已排期卡片离开视野后，仅在对应的左侧或右侧边缘显示小箭头，隐藏标题和属性。横向滚动时，边缘箭头保持固定，显示名称列时也一样。悬停可查看任务名及日期范围，点击可跳回任务。未排期行保留简洁的名称与 No date 提示。

**Dependencies（依赖关系）**向数据源添加本地 **Blocked by** 与 **Blocking** 关联字段，不改写已有导入字段。通过卡片连接点或 Dependencies 菜单选择前置任务，也可把金色圆点从前置任务拖到后续任务。圆点与短横线保持中心对齐，悬停放大时仍保持对齐；拖动时连续的实线箭头跟随鼠标，并描边提示目标卡片。在时间线空白处松开会按落点日期创建已关联的新页面，沿用前置任务的时长，并遵循当前的重叠顺延设置。新卡片可直接输入名称，按 Enter 或离开输入框保存。拖动中按 Escape 或在时间线外松开会取消，不创建页面。只有松开在卡片上才连接已有任务，同一行的空白处仍用于新建。半透明黄色箭头连接可见任务，随日期编辑更新，拖动连线时也保持在卡片和标题下方；激活箭头可删除依赖。Table 中编辑任一关联列都会更新同一张依赖图。页面属性只保存 Blocked by，Blocking 根据它反向计算，包含当前筛选／加载范围外的记录。拒绝自关联、其他数据源的目标和循环依赖。

Dependencies 菜单默认选择 **Shift only when dates overlap（仅在日期重叠时顺延）**，也可选择 **Do not shift automatically（不自动调整日期）** 和 **Shift using（排期使用的日期）**。在数据库工作区添加依赖或修改该日期属性时，重叠的后续任务会移到最晚前置任务结束的次日，保留时长，并递归处理包含筛选范围外记录的下游链。仅打开视图或修改设置不会调整已有日期。无日期记录保持无日期；如需顺延的后续任务含时间、时区或由文档控制日期，会在入队前阻止本次操作。排期作用于 Timeline 和 Table 工作区的编辑，直接 API、Markdown 和记录抽屉的修改不会自动重排。每条受影响记录和视图行顺序保留各自的版本校验；冲突后停止后续保存并保留剩余草稿，因此多记录操作可能部分保存。**Manage in Calendar** 打开或创建使用同一数据源、日期字段的本地 Calendar 视图，不连接外部日历服务。

新建 **People** 字段可选择多个本地通讯录联系人，**Manage people…** 打开现有联系人管理器。新建 **Relation** 字段可选择同一数据源的其他记录。不可用的引用保留原始值，直到用户明确取消选择。导入的 People／Relation 字段仍按原有只读方式显示。

**Chart（图表）**提供柱形、条形、折线、环形和数字汇总。通过 **Configure chart** 或 **View settings → Layout** 配置。在 **Chart type** 下直接点击柱形、条形、折线、环形或数字汇总图标，蓝色边框表示当前类型；悬停可查看名称，也可用 Tab 和 Enter/Space 选择。**Data** 区设置类别（**What to show**）、**Measure**（计数或数字属性）、计算方式、排序及日期分桶。**Series by** 用第二个属性拆分柱形或折线系列；柱条可以堆叠或并排显示，正负值分别从零基线向两侧堆叠。日期类别使用 Count 或 Sum 时可启用 **Cumulative**，按日期先后累计。平均、最小和最大值仍按单个分桶计算。

**Style** 提供颜色、四档高度、数据标签、图例、网格线和坐标轴名称。折线可启用平滑曲线、渐变填充；环形图可显示中心总值，并在足够大的扇区上显示百分比。设置只展示当前图表类型适用的选项。切换图表类型并保存设置时，保留数据库当前的滚动位置。图表适配可用宽度，类别密集时在图表内部滚动。悬停或聚焦图形可查看数值，点击或按 Enter/Space 打开对应记录表。累计点的记录表包含截至该日期参与累计的记录。打开记录后可编辑页面；Escape 关闭记录表并恢复焦点。点击图例可临时隐藏或显示类别、系列，不改变已保存的筛选条件或记录；重新加载视图后恢复显示。

**Save chart as…** 可下载 PNG 或独立 SVG，支持透明背景。导出包含视图标题、当前可见图形和图例，并保留解析后的图表样式。宽图的 PNG 分辨率设有上限。下载已在浏览器中验证；Android 原生下载尚未经真机验收。

统计使用筛选和搜索后的全部记录，不受展示加载上限影响。求和、平均、最小值和最大值仅使用有限数字，平均值排除缺失值；数字折线在缺失观测处断开。多选记录在每个选中的类别、系列中各贡献一次，因此类别或堆叠总计可能超过唯一记录数。数字汇总直接统计记录，不因分组重复计数。日期采用存储的日历日期，周分桶从周一开始；缺失日期单独分组，不参与累计。超过 200 个类别或 50 个系列时提示缩小范围，不会静默截断。环形图要求数值非负且总和大于零。设置保留修订冲突检查，不改写页面正文。尚未实现保存下钻视图、公式／汇总执行和复制图表图片到剪贴板。

**Feed（动态流）**使用居中的单列圆角卡片：有 `author` 元数据时显示作者首字头像和姓名，随后是相对更新时间、大标题和可换行的横向属性。正文 YAML/Pandoc 中的作者信息优先于共享属性；无作者时显示中性页面图标与更新时间。日期范围显示起止日期，人员显示姓名，关联显示页面标题（可点击打开可用的本地记录），状态使用彩色胶囊标签。仍支持可选封面和 CommonMark 正文预览。点击卡片标题即可打开页面；鼠标悬停时仅轻微增强卡片边框与阴影，标题行不高亮。

**Layout → Page content** 切换截断预览和完整正文。**Property visibility** 提供属性搜索、**Shown in feed / Hidden in feed** 显示与隐藏分区、**Hide all / Show all**，以及拖动或上下按钮排序。标题始终保留。修改会自动生效并保存到当前视图，菜单保持打开，保存失败时保留草稿。筛选、排序和分组沿用共享控件。预览经过清理，原始 HTML 按文本显示，不支持的 Notdown 语法可能保持字面形式。查看预览不会改写源文件。尚未实现评论、回应和阅读统计。

Notion 导入识别这些布局名称，并保留完整远端定义；能识别的日期与分组引用会进行映射，无法映射的图表配置、时间轴依赖和协作功能会给出导入警告，不声称行为完全一致。已有导入中降级为表格的视图不会自动转换。

## 仪表盘、表单和地图

可用 `npx tsx scripts/create-database-extra-examples.ts "<example-vault-path>"` 向指定示例 vault 添加三组关联演示和导航页。脚本拒绝创建重名示例，并校验原有 Markdown 页面内容未改变。

**Dashboard（仪表盘）**区分查看和布局编辑模式。新仪表盘进入编辑模式，已有仪表盘默认用于查看。可从任意本地数据库选择已保存视图，也可为组件新建表格、图表、列表、看板、日历或时间轴。最多十二个组件，每行最多四列。标题位于对齐的卡片上方，悬停或键盘聚焦时显示操作按钮；窄屏自动排列为单列。

编辑时可用拖柄在行内、行间移动组件，或拖到“添加新行”。标题菜单和右键菜单提供替换、复制、移除及键盘可操作的移动命令。拖动列间分隔线调整宽度比例，拖动行下方分隔线调整统一行高；聚焦分隔线也可用方向键调整。“保存布局”使用捕获的版本保存，“取消编辑”放弃草稿。保存失败时保留本标签页草稿，刷新后仍可恢复；旧版本不会自动覆盖其他窗口的布局。打开旧仪表盘不会改写原有引用。

“配置组件”可就地调整名称、视图类型、属性、筛选、排序和分组。组件设置独立于来源视图，复制组件后可以分别配置，不会改动原数据库标签。“全局筛选”按数据源设置条件，对使用该源的所有组件生效；可同时设置多个源的条件，但不会将不同源的同名属性自动视作同一字段。搜索覆盖所有组件。查看模式中的设置暂存在当前浏览器标签页；使用“保存组件设置”持久化，或用“重置临时筛选”清除。

图表统计所有匹配记录并随卡片尺寸变化；其他组件限制展示记录数，表格默认 50 条、其他布局默认 100 条，视图明确设置的限制优先。表格、列表和看板组件可打开页面；字段编辑和记录移动在来源视图或页面中进行。“打开来源视图”打开被引用的数据库；来源不可用时保留可替换的占位组件。工具栏支持全屏。未实现嵌套仪表盘、表单组件、远端权限、AI 生成或跨源同名属性自动匹配。

**Form（表单）**将可见的可写属性转换为问题。标题始终必填；在“布局 → 必填问题”中配置其他必填项。支持文本、数字、复选框、日期、单选／状态、多选、URL、邮箱和电话。提交通过带版本检查的 vault API 创建一条记录。失败时保留答案，同一浏览器标签页刷新后也能恢复草稿。不提供公开链接、匿名收集、条件分支或附件上传。

**Map（地图）**使用 **Place（地点）**属性，或已有数值类型的“纬度”和“经度”属性（WGS84 度数）显示记录。创建地图时优先复用第一个地点属性，缺少时自动添加；已有经纬度视图保持原配置。**地图依据**可切换地点字段或经纬度。在记录卡片、表格单元格或记录面板中添加／编辑地点：手动输入名称、地址和坐标，或明确点击**搜索地点**，选择结果后**保存地点**。清除只移除此属性值。地点名称和地址参与共享文本搜索、筛选和字母排序。

**高度**提供小、中、大、超大四档；**着色依据**使用单选／状态／多选选项颜色。多选使用第一个已选选项，缺失值显示为灰色未分类标记。图例跟随当前标记的记录。这些设置也在 **视图设置 → 布局**中提供。可平移、缩放、**显示全部地点**或**在地图上显示**来定位记录。点击标记会显示包含页面标题及**在 Google Maps 中打开**链接的浮层；记录卡片也支持打开页面和 Google Maps。坐标缺失或无效的记录仍留在列表中。按共享筛选／搜索／排序后的顺序，最多标记前 100 条有坐标的记录；其余记录留在列表并显示提示。展示加载上限不会悄悄移除地图候选记录。

OpenStreetMap 底图需要网络，并向底图提供方发送地图区域请求；不发送记录标题。明确触发地点搜索时，仅将输入的查询发送给基于 OpenStreetMap 数据的公共 [Photon 地理编码服务](https://github.com/komoot/photon)。搜索覆盖和可用性因地区而异；出错时保留输入，离线可手动输入坐标。输入过程中不会自动搜索，也不会在选择并保存前替换已有地点。只有打开 Google Maps 链接时才向它发送坐标。地点值以 `{ name, address, latitude, longitude }` 保存在共享页面属性中，编辑时保留额外字段。保存继续使用页面／字段版本校验和草稿恢复；地图设置继续使用视图版本校验和冲突恢复。未实现 Notion Place 属性导入、地址自动转换、路线规划和后台地理编码。

设计参考核对于 2026-11-04：[仪表盘](https://www.notion.com/help/dashboards)、[表单](https://www.notion.com/help/forms)、[地图](https://www.notion.com/help/maps)和 [Kurashi 地图视图指南](https://kurashi-notion.com/en/blogs/notion/mapview)。这些本地布局不代表与 Notion 全部功能等价。

## Wiki

视图下拉列表中，每个集合视图的 **···** 在旁边展开 **View options**，提供 **Rename**、**Edit view**、**Copy link to view**、**Duplicate view** 和 **Delete view**。打开操作菜单时保持当前视图，点击 **Edit view** 才打开目标视图的设置。Home 保留页面选项。数据库菜单打开期间锁定背景滚动，包括表格内部的滚动区域；长菜单自身仍可滚动。关闭菜单后恢复背景滚动。

Wiki 是一种数据库容器，在 **Databases** 列表中显示为 **Wiki · Home and page views**。列表的 **New wiki** 创建根层 Wiki；正文 `/` 菜单搜索 **wiki**，选择 **Wiki**，会在当前页下新建 Wiki 并插入页面入口。手机的插入块菜单和数据库列表也提供 Wiki。

普通页面的右上角／侧栏页面菜单提供 **Turn into wiki**。转换沿用页面 ID、Markdown 文件、正文、图标及父位置；原正文成为 Home。Wiki 只有一个页面数据源，初始 **All pages** 使用 List 布局；Home 使用正文编辑器，集合视图可新增 Table、List、Gallery、Board、Calendar、Timeline、Chart 和 Feed。Home 不显示数据库筛选／分组工具；集合视图不提供新建／接入数据源、切换来源和显示数据源标题。普通数据库及数据库记录不提供页面转 Wiki。

直接和嵌套子页面按原父关系加入页面集合；子数据库及其记录保持独立，不被压平或当作 Wiki 页面记录。新建子页面以及移动页面／子树进出 Wiki 会更新成员关系；页面属性与集合视图共用原页面数据。普通数据库可以链接 Wiki 的页面源；存在外部引用时，Undo 会阻止移除共享来源，保留已有数据库和引用。

Wiki Home 默认采用 **Full width** 布局，标题、导航与正文共同使用可用内容宽度；Home 和集合视图共用封面、横排图标／标题、面包屑、内容边距与胶囊下拉视图入口；切换时只更换内容区及右侧工具。Wiki Home 不提供单独的宽度开关，Undo 后恢复普通页面原先的宽度设置。

打开 Wiki 默认进入 **Home**。标题下的视图下拉菜单在 Home 和集合视图中相同，列出 Home、所有已有视图及 New view，并标记当前视图；New view 在 Home 即可创建集合视图，提交前会收取正文输入，取消时保留 Home。Home 右侧 Search 搜索 Wiki 页面；集合视图显示筛选、排序、视图设置及 New 等工具。Home 的源码／分栏等编辑模式和页面属性从右上角页面菜单打开。导入时保留的独立 Home 子页继续承载原正文，外层显示 Wiki 容器的封面、图标与标题；可在集合视图中编辑该容器名称和图标，不合并或改写原子页。Wiki Home 的页面菜单提供 **Undo wiki**：解除该容器、数据源及视图，把 Home 恢复成普通页面，保留正文、页面身份、子页面／子数据库位置和每页已有属性值。字段定义、视图及转换前后 metadata 归档到 `.history/database-transactions/`，目前没有自动重新应用归档的界面。原有链接仍指向同一个页面，不批量改写正文。

Notion 导入的 Wiki 采用同一种单数据源边界。早期导入恢复出的独立 **Home** 子页面继续保留，Undo 后仍在原位置，不合并、删除或覆盖原页面正文。若独立 Home 已删除或移入回收站，独立文件格式的 Wiki 进入有效集合视图，不创建空 Markdown 替身，也不恢复已删除内容；旧格式仍可使用原有真实宿主页。将当前打开的 Wiki／数据库移入回收站后，离开该集合视图并更新侧栏，可从 Trash 恢复。如果旧 Wiki 的来源已被其他数据库共享，Undo 会提示并停止，保留现有资源。Notion 的当前用户 Owner 筛选、Verification 验证与通知尚未在本地模拟。

转换前收取 pending 编辑；转换及 Undo 在知识库锁内校验页面／数据库版本，冲突归档双方，不强制重试。转换更新数据库 JSON 与页面元数据；已有页面 Markdown 不会因转换而重新序列化。独立 Home 的导入 Wiki 在 Undo 时恢复一个普通容器页面，其原 Home 子页保持原文和位置。

行为参考 [Notion Wiki 官方说明](https://www.notion.com/help/wikis-and-verified-pages)：Notion 提供页面转 Wiki 和 Undo Wiki，默认有 Home、All pages、Pages I own；官方未明确说明 Undo 后自定义属性和视图配置的完整去向。上述保留／归档规则是 Notdown 的明确契约，本地不伪造账户对应的 Pages I own。

数据库从应用 Trash 再次删除后，数据库 JSON、Wiki 的真实 Home 及所选子页面进入系统回收站，历史中保留恢复材料。已删除容器不再生成侧栏入口或出现在数据库和数据源列表中；引用它的数据源视图保持 Link，并显示来源不可用，不接管其记录。旧格式保留的宿主页元数据只用于恢复，不会把缺失宿主误当成从未有宿主的数据库。

## 数据源管理

完整数据库和正文内嵌数据库使用 **View settings → Manage data sources**，也可从 **Source → Manage data sources** 打开。来源管理在右侧设置面板内替换当前内容，**Back** 返回上一层，**Close** 关闭整组面板。数据库可以包含多个数据源，每个视图选择其中一个数据源。

面板将本数据库拥有的来源列在 **Source**，外部接入的来源列在 **Linked**。每个来源占一行，显示名称、当前数据库中的视图数量和 **···** 详情入口。详情保留原数据库、其他使用它的数据库和各自视图；视图链接打开准确的数据库与视图。悬停来源名称可查看所属关系和视图名称。

查看全知识库的数据源：侧栏 **Databases → Data sources**。列表每个数据源只占一行，分列显示名称、原数据库和使用位置／视图，可按数据源、数据库或视图名搜索。当前数据库菜单的 **Browse all data sources** 也可查看同一列表。列表是只读关系投影，不复制记录或写回元数据，回收站中的数据库不会显示为活跃使用位置。

完整数据库包含多个数据源时，默认按 **数据库标题 → 当前数据源标题 → 视图标签** 排列；切换视图时，第二级标题随其数据源变化。单数据源的完整页默认只显示数据库标题；内嵌数据库默认只显示当前数据源标题。**Layout → Show data source titles** 可覆盖数据源标题的默认显示，显式选择会保存。视图标签的悬停提示显示所属数据源。

完整数据库和内嵌数据库显示的当前数据源标题可以直接点击编辑，不再作为下拉菜单入口。输入后自动保存，Enter 或离开输入框立即保存；Escape 放弃尚未提交的名称。修改只更新数据源名称，数据库容器名称、视图名称和正文引用保持原值；Linked 位置改名也会更新同一个来源。来源不可用时标题只读。保存失败或版本冲突保留名称草稿，显式重试仍使用原版本，不自动覆盖其他窗口的修改；数据源管理从 **View settings → Manage data sources** 进入。

来源分组和共享数据、独立视图的语义参考 [Notion 数据源管理说明](https://www.notion.com/help/data-sources-and-linked-databases)；数据库／数据源标题层级参考用户提供的 Notion 界面。

- **Source → Add data source** 在当前数据库中创建独立的字段和记录集合，并添加一个同名 Table 视图；不会另建数据库宿主页。点击 **Create data source** 才保存，返回上层或关闭面板不会创建资源。
- **Link existing data source** 可按数据源或所属数据库名称搜索本知识库中的数据源。接入后添加一个本地 Table 视图；字段和记录继续共享，编辑会在引用同一数据源的其他数据库中生效。视图的筛选、排序和布局独立保存。
- 接入不会复制 Markdown、移动记录或改变数据源的所有者；从接入位置新建的记录仍归原数据库宿主页。已接入的源不会重复出现在候选列表，回收站中的来源数据库也不列为可接入对象。
- **Source / Linked** 列出当前来源及所属关系，点击来源名称切换到其视图。新建／接入会先保存当前单元格草稿，再检查数据库版本；接入还检查所选源的版本。冲突保留输入并显示原因，不自动覆盖其他窗口的更改。

来源行的 **···** 打开独立小菜单，提供 **Copy data source ID**、**Move to**、**Move to Trash**，也可查看来源关系。自有的普通数据源可以移动到其他普通数据库：来源及页面 ID 保持不变，记录根页面改归目标数据库，已有视图继续引用同一来源；原数据库中的视图变为 Linked。移动前校验来源、原数据库和目标数据库的版本，拒绝循环归属及由文档 metadata 控制的记录父位置。Linked 入口不能代替原数据库移动或删除来源；Wiki 的页面源继续遵循 Wiki 转换边界。

数据库删除沿用页面的 Trash。数据源 **Move to Trash** 也为可恢复删除：字段、视图引用和 Markdown 保留在原位置，来源及其页面暂时隐藏，外部引用显示来源在 Trash；恢复后重新可用。侧栏 **Trash** 列出被回收的数据源及页面数量，**Restore** 恢复整个来源；管理面板的 **Trashed data sources** 也提供恢复入口。单独进入 Trash 的来源不会因恢复其数据库而被自动恢复。

**Trash → Empty Trash** 同时清理已回收的数据源及其记录和子页面，保留活动数据库及其他来源。来源定义的删除有历史恢复材料，外部 Linked 视图保留引用并显示来源不可用。清理校验来源、所属数据库和全部记录的版本；遇到冲突或系统回收失败即停止，不自动覆盖或重试。

数据源管理回归见 `tests/unit/database-sources.test.ts`、`tests/unit/database-source-lifecycle.test.ts` 和对应浏览器用例，覆盖归属、版本冲突、原文保留及回收与恢复。

## 多种布局

Gallery 默认在 **View settings → Layout → Card preview** 使用 **First image（第一张图片）**，查找正文第一张图片，无图时回退到首块。**First block（第一个块）**只显示首个正文块的文字、图片或视频；**Page preview（页面预览）**从正文开头按顺序显示多个块，填满卡片可显示的预览范围，超出部分裁掉，不滚动或撑高卡片。还可选择 **Page cover** 或 **None**，**Fit image** 控制完整适配或裁剪。完整 YAML／Pandoc 标题块不参与预览。页面图标位于卡片标题旁，遵循 **Show page icon** 设置。已经明确保存的预览选择继续保留，预览不会改写 Markdown。

视图设置、标签菜单和新建视图中提供 **View icon（视图图标）**，可搜索完整内置 Lucide 符号库。每个视图独立保存，标签、溢出选择器、侧栏及 Wiki 选择器同步显示；**Use default icon** 恢复布局默认图标。复制视图会保留图标。视图符号与页面的 emoji／图片图标、数据库图标分别设置；保存继续遵循 CAS 冲突保护。

Notion 当前的[画廊说明](https://www.notion.com/help/galleries)采用首块预览；其[图标发布说明](https://www.notion.com/releases/2022-11-17)在发布时为数据库视图和属性提供 600 多个内置符号，这个历史数量不能代表当前精确总数。Notdown 使用自己内置的 Lucide 图标库。

**+ New view** 提供与 Notion 类似的图标网格，切换标签不会复制记录。Table 保留单元格编辑；List 是紧凑记录列表（[布局与属性显示](DATABASE-LIST.zh-CN.md)）；Gallery 使用卡片网格；Board 按 Select、Status 或 Checkbox 属性分组；Calendar 按日期属性显示月或周。

新视图在同一个浮层内设置名称、布局和数据源，点击 **Done** 创建；点击外部或按 Escape 取消创建。已有视图的 **View settings** 使用右侧面板，子设置在同一位置切换，属性选项继续使用锚定入口的级联菜单。已有视图的布局、预览、属性显示与顺序、分组、筛选、排序、图表选项、视图名和图标均自动生效并保存，保存时菜单保持打开；可用 ×、Escape 或点击外部关闭。新建视图和字段结构编辑保留明确确认。保存失败时保留输入并显示原因，也可明确选择 **Discard menu changes** 放弃本次菜单草稿；不会以最新版本号强制覆盖其他窗口的改动。

点击当前视图标签或右键任一标签，打开标签下方的 **View options**：**Rename**、**Display as**、**Edit view**、**Source**、**Copy link to view**、显示／隐藏数据源标题、**Duplicate view** 和 **Delete view**。右键操作其他标签时不会切换当前视图。复制沿用原来源、字段选择、筛选、排序和布局，只创建新视图。

`[Overview](#database/<database-id>?view=<view-id>)` 这样的 Markdown 链接会在当前知识库内打开指定数据库视图。`#databases` 和 `#vault/list` 链接打开对应的应用视图；普通标题和块片段仍在文档内定位。跳转会先保存待处理输入，遇到冲突则停止，并纳入后退／前进历史。

删除某个来源在当前数据库中的最后一个视图时，会先选择 **Delete view only**，或 **Delete view and data source**。前者保留来源和全部页面，允许数据库暂时没有视图，再用 New view 恢复显示；后者将自有的普通来源及其页面一起移入 Trash。Linked／Wiki 不提供代删原来源的选项。删除同时校验视图和数据库版本，连同来源删除还校验来源版本；冲突保留恢复记录，不强制重试。尚未提供逐个视图固定到侧栏的入口，侧栏仍按既有 Database children 设置展示视图。

工具栏空间不足时，当前视图的名字和图标保持可见，其他放不下的视图收进 **n more…**。从菜单切换后，新选中的视图也会显示在工具栏中，不改变保存的视图顺序。菜单列出全部视图、当前选择和各自的操作入口，可搜索视图名，并提供 New view／New data source。搜索记录也在工具栏原位置展开，Escape 关闭并清空，不另占一行。

- **OPEN** 隐藏时标题使用完整可用列宽；悬停或聚焦记录行后才显示按钮并为它留出空间，键盘和手机仍可正常打开记录。
- 拖动 Table 列标题右侧边缘可调整该列宽度，悬停或拖动时边缘显示蓝色；按 Esc 取消本次拖动。也可聚焦分隔线后按左右方向键（Shift 加大步长）。列宽按视图保存，支持分组表头和内嵌数据库；保存冲突时保留可恢复草稿。
- **Layout** 可设置数据源标题、页面图标、表格竖线、全部内容换行，以及 Side peek / Center peek / Full page 打开方式。**Load limit** 控制首批显示 25、50、100 或全部记录，**Load more** 继续显示；不改变底层记录数量。
- **Property visibility**、**Filter**、**Sort**、**Group** 分别打开子菜单；**Copy link to view** 复制指定视图入口，**Source** 显示所用数据源，**Edit properties** 打开字段列表。已有视图不跨数据源重新绑定。
- 表头菜单提供字段改名、空字段类型变更、按此字段筛选／排序／分组、冻结当前列、隐藏、单列换行和左右插入字段。含记录值的字段不能直接改类型；被视图引用的日期／分组字段不能改成不兼容类型。冻结、隐藏及换行设置属于当前视图。
- Table、List、Gallery、Board 共用分组设置。新视图沿用当前记录顺序，随后可独立筛选、排序和设置显示字段。
- 分组表格为每组重复显示列标题和 **New page**，在组内新增记录会填好分组属性。组标题箭头可折叠／展开并保留到当前视图；标题旁的 **···** 提供 Edit groups、显示记录计数、隐藏组和颜色设置。选项组调色同步更新该选项标签；空值／勾选组颜色保存在视图中。隐藏组可在 **Group** 子菜单重新显示。
- 组菜单的 **Move to Trash** 会先显示本次筛选范围内的记录数量并确认，再把这些页面及其子页面移入可恢复的回收站；不受首批加载数量限制。逐条写入均校验页面版本，若中途冲突则停止并明确报告已完成数量，不强制覆盖剩余页面。

- 卡片标题打开现有记录面板，可编辑原页面正文和属性。手机继续打开完整记录页。
- **View settings → Layout** 切换布局；**Property visibility** 控制显示字段。Gallery / Board 可选卡片大小、页面封面、正文文字预览和图片适配。正文预览当前为文字摘要，文件属性图片及完整富文本预览尚未接入。
- **Group by** 选择分组字段，可隐藏空组、隐藏指定组，并用上下按钮排列分组。Board 跨列拖动会保存对应属性；同列卡片手动排序尚未提供。受 YAML/Pandoc 或只读字段控制的值不能通过拖动覆盖。
- 新建 Board / Calendar / Timeline 时没有选择相应字段，会新增 Status / Date 属性。旧视图缺少字段时显示设置入口，不在读取时修改数据。
- Calendar 提供 Today、前后导航、月／周切换、无日期列表以及按日期新增记录。多日任务在一周内以一张连续卡片横跨日期，跨周后在下一周续接；重叠卡片各占一层，周行高度随卡片内容调整。周末有底色，今日有红色圆形标记。状态标签和完整日期范围按可见属性顺序展示。
- Calendar 的 **Property visibility** 分为 **Shown in calendar（显示于日历）** 与 **Hidden in calendar（隐藏于日历）**，支持搜索、Hide all / Show all、拖动排序和可用键盘操作的上下按钮；Name 始终保留。**Layout → Start week on** 可选择星期一或星期日。通过界面新建的日历默认星期一开始；未显式设置的旧视图保留星期日。
- 拖动全天卡片会保留时长和抓取点对应日期，包括跨周续段。依赖排期也适用于 Calendar 工作区的日期拖动。带时间／时区的记录按其日期部分显示，通过记录属性改期；不提供时区切换或外部日历集成。
- 多个筛选和排序会完整保留；**All conditions / Any condition** 对应 AND / OR。选项条件保存稳定选项 ID，数字按数值比较，日期比较使用日期部分。隐藏记录不会删除原页面。
- 所有视图沿用页面和字段版本校验、草稿恢复及冲突归档。桌面和手机共用实现；触摸端通过记录属性改组／改期，原生 HTML 拖动主要供鼠标操作。

## 手机使用

手机 **Pages → Databases** 打开数据库列表，**New database** 新建根层数据库；页面树中的数据库打开完整表格，展开后可进入记录。普通页面底部 **Insert block → Database** 选择 Inline／Full page，以及新建或链接已有数据源。当前方言不支持数据库引用语法时只能选 Full page。Inline 保留在正文里，右侧 **Open as page** 打开完整表格，父页面中的数据库块菜单 **Turn into page** 转为页面入口。

手机表格支持编辑标题、字段、基本属性值、新增记录、新建视图、筛选、排序和搜索；宽表格在自己的区域横向滑动。点击记录的 **OPEN** 进入完整页面，编辑属性和正文后用 **Back to database** 返回；手机使用完整记录页。切换页面、视图或进入数据库前先保存待处理输入，冲突时保留原版本草稿并阻止导航。电脑导入后经云同步到手机的 full-page 和 inline 数据库使用相同入口；Notion 导入向导仍在电脑端使用。

手机直接编辑记录时，页面及字段版本一并保存在恢复草稿中；重开草稿不会自动采用新字段版本强制覆盖。公式、汇总、关联、联系人、文件与文档 metadata 控制的属性继续遵循下述只读边界。

## 创建位置与页面树

数据库可以位于知识库根层，也可以作为普通页面的子项。侧栏用同一棵页面树展示数据库和记录：点击数据库打开表格，展开后默认显示它的记录；点击记录打开普通页面。记录不会同时作为根层页面重复显示。在 **Workspace settings → Appearance → Sidebar → Database children** 中可改为 **Views**，展开后显示保存的视图，点击打开对应视图；记录仍保留在数据库中。目录树默认折叠，可在同处设置 **Default expanded levels**（0–10 层或全部）。

正文 `/database`、`/inline` 或 `/link` 都可找到同一个 **Database** 入口。创建面板选择名称、Inline／Full page，以及 **New data source** 或 **Link existing data source**；提交前不会创建资源，取消不写入数据库。创建前先保存待处理的正文，链接已有来源时同时校验其版本，失败保留创建草稿。

两种展示都在当前页下创建同样的 `databases/<id>.json`。Full page 创建后打开数据库，父页保存官方 `<database inline="false">` 引用；不支持该语法的方言使用普通 Markdown 链接。Inline 使用 `<database inline="true">` 嵌入同一个数据库工作区：紧凑可编辑标题、视图标签、右侧工具及表格，右侧 **Open as page** 打开完整页面。外部来源在数据源标题前的图标右下角显示向右上方的链接箭头，视图标签仅显示图标和名称。完整页面隐藏数据源标题时，箭头改在数据库标题图标上显示；记录仍属于原来源，不复制定义或记录。Linked-only 数据库允许 `dataSources: []`，只有引用外部来源的视图，之后也可增加自有来源。

编辑器只有一种 `block.database` 节点；inline／full page 是入口的展示属性，链接关系属于 JSON 中视图的数据源引用。块手柄或页面入口的 **··· → Turn into inline database** 将入口展开为内嵌视图；父页面中的内嵌块菜单 **Turn into page** 将其收为页面入口。完整数据库不再提供重复的转换菜单，转换在父页面的目标块上完成。转换先保存待处理正文和单元格，保留数据库 ID、来源、视图和记录，不重建 JSON。根层数据库没有父页时无法转成 inline；父页方言不支持、版本冲突或存在多个同库入口时会说明原因，多个入口需从目标块的菜单转换。

数据库的顶部面包屑按实际父页面层级导航；记录的面包屑可返回所属数据库，根层数据库仍可用 **All databases** 返回列表。标题和图标写入所属 JSON；已有引用的显式显示文字继续保留原文。

新建数据库拥有独立 JSON，不创建空 Markdown。数据库与页面共同进入侧栏树，名称及父位置保存在数据库文件；新记录的 `parent` 指向所属数据源的数据库 ID。页面 API 为现有导航提供同 ID 的兼容条目，并以 `databaseProxy: true` 标明没有 Markdown 正文。普通页面创建／移动不能绕过数据源登记直接塞入数据库，数据库记录也不能通过普通页面移动接口改成其他父级。

宿主页沿用页面移动与回收站规则；回收宿主页时，它的记录随层级隐藏，恢复后重新显示。记录的侧栏移动入口和拖动被禁用；数据库宿主页不提供会产生不完整资源副本的普通页面复制入口。

旧格式数据库继续沿用原宿主页或虚拟条目，读取和展开不会改写磁盘。早期没有宿主页的旧库新增记录仍保存原有 `parent: null`，树中按数据源归属显示；只有显式迁移才改用独立 JSON。新导入数据库直接采用独立文件。

内嵌数据库只显示当前 data source 标题，容器名称继续属于完整数据库。正文和工具栏保持页面原宽度；表格列溢出正文宽度时，只有数据区扩展到可用页面宽度，并在内部横向滚动，不修改页面 Full width 设置。分栏内的数据库保留在所在栏内滚动。

内嵌数据库的视图胶囊、工具栏、选项单元格和卡片使用数据库自己的控件样式；通用内容块的按钮默认样式不会覆盖它们。开发服务与生产构建均通过独立临时知识库回归，测试见 `tests/e2e/database-inline-styles.spec.ts`。

## 独立数据库文件

数据库存储升级为 `databases/<database-id>.json`，Database 与 Markdown Page 是同级资源。文件保存数据库展示信息、自有数据源（字段及 `pageIds`）和视图；视图的 `dataSource` 同时指定 `databaseId` 与 `dataSourceId`，跨库时显示链接来源箭头，仅引用所属库，不复制定义或页面。普通数据库不创建空 Markdown；Wiki 的 `homePageId` 指向真实正文页。页面属性仍保存在 `metadata.json`，页面 API 的数据库宿主／成员字段为兼容投影。

旧数据库格式保持可读；同步收到旧格式资源也保留其宿主页和资源格式，不因下载顺序隐式迁移。迁移必须显式执行并校验预览版本，保留 ID、未知字段和恢复记录。迁移后的旧定义退出活跃读取，删除 JSON 不会从旧定义重建数据库。成员、页面及数据库文件的联合写入仍走知识库锁、CAS 和可恢复事务。

```json
{
  "version": 1,
  "id": "projects",
  "kind": "database",
  "title": "Projects",
  "parent": null,
  "dataSources": [
    { "id": "tasks", "title": "Tasks", "properties": [{ "id": "name", "key": "title", "name": "Name", "type": "title" }], "pageIds": [] }
  ],
  "views": [
    { "id": "table", "name": "Table", "type": "table", "dataSource": { "databaseId": "projects", "dataSourceId": "tasks" } },
    { "id": "linked", "name": "External", "type": "list", "dataSource": { "databaseId": "another-database", "dataSourceId": "external-source" } }
  ]
}
```

示例省略真实 UUID。自有来源只定义在所属库；外部来源仅以视图引用出现。`pageIds` 是成员关系的唯一持久真相，页面 API 的 `dataSourceId`／`wikiMember` 是读取时投影，不在 `metadata.json` 再缓存一份关系。`revision`、`linked`、`ownedDataSourceIds` 等 API 字段也不写回文件。导入宿主的来源信息和未知字段保留在可选 `pageMetadata`；迁移另保留完整 `legacyPageMetadata`。普通页面未知属性仍在原 JSON 页面记录中。

```powershell
node --import tsx scripts/migrate-database-files.ts <vault-path>
node --import tsx scripts/migrate-database-files.ts <vault-path> --apply
```

第一条预览，第二条以刚取得的预览版本执行，HTTP 也提供同等的两步接口。迁移前后文件完整记录在 `.history/database-migration-<uuid>.json`；空宿主原文归档后移出 `pages/`。非空的普通数据库宿主、不同 ID 的旧宿主、歧义／缺失来源所有权和版本变化会中止并保留原文件，需先明确映射，不能依靠重试强制覆盖。旧知识库不会在打开时自动迁移。同步中的设备需使用支持独立数据库文件的同一版本。

## 旧格式存储契约

`metadata.json` 的既有 `pages` 之外增加以下顶层记录，未知顶层和对象字段继续保留：

| 区域 | 内容 |
| --- | --- |
| `pages[pageId]` | `dataSourceId` 指定记录所属数据源，`properties` 保存属性值；数据库宿主页包含 `databaseId`，`parent` 保存页面树位置。 |
| `dataSources[sourceId]` | 数据源名称、字段定义与 revision；新数据源的 `ownerDatabaseId` 指定其数据库宿主。每个字段有稳定 `id`、属性键 `key`、显示名 `name` 和 `type`；选项另有稳定 ID。 |
| `databases[databaseId]` | 数据库名称、宿主页 `pageId`、`dataSourceIds`、`viewIds` 与 revision。 |
| `views[viewId]` | 所属数据库及数据源、表格布局、可见字段、筛选、排序与 revision。 |

标题字段直接绑定页面标题；普通属性仅保存在页面的 `properties` 中。数据源归属和页面父关系分别记录，一个页面至多有一个 `dataSourceId`；有宿主的数据库记录由该宿主页承载。不同视图引用同一组记录，不复制正文。

Wiki 容器记录 `kind: "wiki"`；早期导入的 `notionWiki: true` 继续识别。宿主页记录 `wiki: true`；成员页面的 `wikiMembership` 标记可随页面树重新计算的数据源归属，`parent` 始终保留真实层级。字段和视图继续使用既有资源格式，正文入口复用官方 `<database wiki="true">`，其他方言使用普通链接。

正文不保存数据库记录 JSON，也不增加自定义正文协议。现有 `<database>` 引用语法与资源定义分离；数据库从侧栏或页面引用打开时进入集合视图。备份应复制整个知识库，包括 `databases/`、Markdown 和 `metadata.json`。

## 保存与冲突

所有变更通过 `createVault` 的本地锁和版本校验。字段定义、数据库和视图有独立 revision；单元格同时提交页面 `baseRevision` 和字段定义 `schemaRevision`。旧窗口不能将依据旧字段类型编辑的值直接写入新 schema，也不能覆盖较新的正文。

页面内容仍沿用成对的 Markdown / JSON 历史和冲突记录。数据库资源冲突在 `.history/database-conflicts/` 保存当前和拟写入版本；资源更新在 `.history/database-transactions/` 保存原数据库文件和拟写入资源，联合写入使用可恢复的文件批次。ZIP 与 Git 检查点包含独立数据库文件。这里提供可恢复证据，目前没有数据库历史回滚界面。

表格草稿按知识库和数据库存于当前标签页的会话存储，保留最初的页面及字段版本；恢复草稿不会自动换成新 revision 强制重试。保存失败时的 **Discard draft and reload** 明确丢弃本标签页草稿后重新读取磁盘数据；Retry save 继续校验原版本，不自动采用其他窗口的新版本。

## Notion 导入

在侧栏 **Import → Import from Notion API** 输入页面、数据库或数据源 URL / ID，预览后导入副本。数据库字段和记录会转为上述本地模型；正文继续使用 Enhanced Markdown，原始 JSON、Markdown 和视图配置保留在导入归档。具体权限、分页、重复提交及安全边界见 [Notion 导入](NOTION-IMPORT.zh-CN.md)。

| Notion 数据 | 当前行为 |
| --- | --- |
| 基础属性和选项 | 转为本地字段定义和可编辑值，保留来源配置。富文本属性显示为文本，原始富文本保留。 |
| Relation | 第二遍解析同批已导入目标；未导入或无权限目标保留来源引用及未解析状态，不按标题合并。 |
| People / Files | 保留来源结构，当前界面只读；不自动合并本地联系人或下载文件。 |
| Formula / Rollup / 未知属性 | 保留定义和导入时结果，作为只读快照；没有本地计算引擎。 |
| 远端视图 | 尝试读取并保留原始配置，按可支持的类型创建本地视图，恢复可见字段、支持的分组属性、日期字段和卡片预览配置；其他布局降级成表格。尚未映射的远端条件、状态大组、子分组和配置保留原始定义并提示。当前筛选导入仍仅执行可准确映射的文本 contains / AND，排序仅映射支持的基础类型；本地设置提供更多条件。 |

早期导入若将字段对象顺序直接存为默认列序，重新打开时会利用已归档视图修正显示；无可用视图则将标题列置首。这是读取时的兼容显示，不批量修改知识库文件。已有自定义列序或显示列集合继续保留。保存视图设置、筛选或排序不会重置当前列序。

## 当前边界

- 提供十一种本地布局：Table、List、Gallery、Board、Calendar、Timeline、Chart、Feed、Dashboard、Form、Map。公式／关联汇总属性计算尚未实现；图表聚合不代表已支持公式或关联汇总执行。
- 数据库可经 Trash 恢复或送入系统回收站；界面暂不提供字段删除／复制、已填值字段的类型转换、现有页面加入或移出集合，以及数据库之间移动记录。
- 视图设置支持多个排序及平面的 All / Any 筛选组合，提供包含、等于、空值和数字／日期比较。暂不支持嵌套条件组和手动卡片排序。
- 关联、联系人和文件没有可编辑选择器；公式快照不会随本地编辑重算，界面始终标注导入结果。
- 不恢复 Notion 权限、评论、自动化和工作区账号；附件 URL 可能过期，导入不能视为完整离线附件备份。
