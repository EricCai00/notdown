# Footnote interactions and body block types

**English** · [简体中文](FOOTNOTES.zh-CN.md)

Check date: 2026-09-23.

<a id="交互"></a>

## Interactions

- The object classification is unified as `inline.footnote`. Pandoc and `^[…]` are only reserved as `inline_notes` syntax adaptation, without independent Inline note objects or insertion commands; the internal structure carrier is used to retain the original text and editing content and does not constitute a new object type. Existing inline footnotes will not be rewritten into reference footnotes in batches.
- `^[…]`Display number superscripts in the page/double column, move the content to the same bottom footnote area, and number them consecutively in the order of appearance with reference footnotes. Support preview, jump, jump back, edit and delete undo. Save `^[…]` that restores the original location, and the ID generated by the view is not written to the file. Inline footnotes can span source code lines and support inline formatting and links, but can only have one paragraph; page editors refuse to split or change to block-level content to avoid saving lost content. Anonymous footnotes do not appear in reuse definition lists.

- When inserting a reference, choose to create a new footnote and fill in plain text, or select an existing definition; enter multiple lines to create multiple editable paragraphs. Cancel does not add a new footnote, and reuse does not copy the definition.
- The Footnote insertion command opens this dialog in both page and source editing. It preserves the insertion position and rejects submission if the owning page changed while the dialog was open.
- A text preview of the footnote body is displayed when the reference in the page is hovered or receives keyboard focus; the preview updates when the bottom body is edited. Missing definitions display a missing prompt.
- Deleting the last reference during page editing will delete the definition and internal source position anchor in the same undo step. Delete some duplicate references and retain definitions; undo and restore references and definitions.
- Opening files, switching dialects, external projections, and direct source code editing do not batch clean up definitions: Text that is not referenced when imported may be data that the user intentionally retains. `[^id]` literals in code fences do not count as references.
- The text is still written as `[^id]: ...`, and the continuation lines are indented by four spaces. The centralized display at the bottom is just the projection of the same ProseMirror document, without adding a new storage protocol.

## Specification review

[Pandoc official footnote document ](https://pandoc.org/MANUAL.html#footnotes) gives examples of multi-block footnotes, subsequent paragraphs and code blocks; its "cannot appear inside other blocks such as lists, quotes, tables, etc." describes the placement position of **footnote definition**, and does not prohibit the footnote body from containing these blocks.

[PHP Markdown Extra official document ](https://michelf.ca/projects/php-markdown/extra/#footnotes) clearly states that footnotes can contain block-level elements, including multiple paragraphs, lists, quotes, etc., and subsequent content is indented by four spaces according to the rules of list entries. Footnotes are not just one piece of inline text, nor is there a uniform whitelist of block types across all Markdown dialects.

This project parses the footnote text according to the current dialect and expansion switches. Unit tests verify that multiple paragraphs, headers, ordered and unordered lists, quotes, code blocks, tables, dividers, definition lists, and block formulas under Notdown can be serialized and re-parsed after editing. Task lists, pictures, HTML, line blocks, Div, charts, etc. still depend on the corresponding syntax switches, and there is no commitment that all upstream renderers support the same combinations.

The bottom insertion menu provides the currently enabled Markdown block and inline formats; it does not provide subpages, columns, product containers such as Tabs and Button, nor does it provide nested footer inlets. This is a local edit menu boundary that does not interpret "all Notion block" as a standard footnote capability. The extended content and unknown content of existing files will continue to be retained by codec and will not be deleted due to menu restrictions. `notion-markdown` still respects official Enhanced Markdown boundaries and does not enable footnotes for this feature.

## Validation
